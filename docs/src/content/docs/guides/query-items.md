Query string values always arrive as strings. Instead of reading `req.query` and converting each value by hand, a GET or DELETE endpoint can declare its query items as a type. The framework then converts and validates the query string before the handler runs, hands you a typed `req.queryItems`, and lists the items in the API docs.

The samples on this page use a `User` entity with `email`, `name`, `role` (`"member" | "admin"`) and `active` fields.

<details>
<summary>The part of <code>.generated/types.ts</code> these samples use</summary>

```ts check title=".generated/types.ts"
// Generated by quickservice build (shortened).
import type { Repository } from "@quickservice/core";

export type User = {
  id: string;
  createdAt: Date;
  updatedAt: Date;
  email: string;
  name: string;
  role: "member" | "admin";
  active: boolean;
};
export type UserCreate = { email: string; name: string; role?: "member" | "admin"; active?: boolean };
export type UserUpdate = Partial<UserCreate>;
export type UserReferences = Record<never, never>;

export interface GeneratedRepositories {
  users: Repository<User, UserReferences, UserCreate, UserUpdate>;
}

declare module "@quickservice/core" {
  interface Repositories extends GeneratedRepositories {}
}
```

</details>

## Declaring the query type

On GET and DELETE endpoints, the first type argument of `Endpoint<Query, Result>` is the query type. Each property is a query item:

```ts check title="endpoints/users/search/get.ts"
import type { Endpoint } from "@quickservice/core";

type Search = {
  /** @minLength 2 @maxLength 50 */
  q?: string;
  role?: "member" | "admin";
  active?: boolean;
  since?: Date;
  ids?: string[];
  /** @default 20 @min 1 @max 100 */
  limit?: number;
};

type UserSummary = { id: string; name: string; email: string };

/**
 * @summary Search users
 * @description Matches `q` against names and emails.
 */
const handler: Endpoint<Search, { data: UserSummary[]; total: number }> = async (repos, req) => {
  const { q, role, active, since, ids, limit } = req.queryItems;
  let query = repos.users.query();
  if (q !== undefined) query = query.where((u) => u.name.contains(q).or(u.email.contains(q)));
  if (role !== undefined) query = query.where((u) => u.role.eq(role));
  if (active !== undefined) query = query.where((u) => u.active.eq(active));
  if (since !== undefined) query = query.where((u) => u.createdAt.gte(since));
  if (ids !== undefined) query = query.where((u) => u.id.in(ids));
  const page = await query.orderBy((u) => u.name).select("name", "email").page({ limit });
  return { data: page.data, total: page.total };
};

export default handler;
```

`req.queryItems` is typed as `Search`: `limit` is a `number`, `since` a `Date`, `active` a `boolean`.

```bash
curl "localhost:3000/users/search?q=ACME&limit=10"
```

```json
{"data":[{"id":"01a146da-b663-7212-b0d6-71457d2a433b","name":"Ana","email":"ana@acme.com"},{"id":"01a146da-b664-72d7-aa2f-7cbd66be8970","name":"Bob","email":"bob@acme.com"}],"total":2}
```

```bash
curl "localhost:3000/users/search?role=member&active=true"
```

```json
{"data":[{"id":"01a146da-b664-72d8-b074-72ee9018fcb1","name":"Cid","email":"cid@globex.com"}],"total":1}
```

The query type can be a type literal, a type alias or an interface. When it is absent or `unknown` (`Endpoint<unknown, Result>`), the endpoint has no query items and `req.queryItems` is `{}`.

:::note
On POST, PUT and PATCH endpoints the first type argument stays the JSON body, and `req.queryItems` is `{}`. Read their query string with `req.query`.
:::

## Supported types

| Item type | Query string | Value in `req.queryItems` | Error when invalid |
| --- | --- | --- | --- |
| `string` | `?q=ana` | `"ana"` | — |
| `number` | `?limit=10` | `10` | `Must be a number` |
| `boolean` | `?active=true` | `true` (only `true` or `false`) | `Must be true or false` |
| `Date` | `?since=2026-01-01` | a `Date` (ISO 8601) | `Must be an ISO 8601 date` |
| String union, string enum or alias (`"member" \| "admin"`, `Role`) | `?role=admin` | `"admin"` | `Must be one of: member, admin` |
| An array of any of these (`string[]`, `Array<Role>`) | `?ids=a&ids=b` | `["a", "b"]` | the item's error, at `ids[1]` |

Values are converted the same way as the `where` filters of the generated list routes. Any other property type fails the build:

```text
endpoints/users/search/get.ts: query item "range" has unsupported type "{ from: number }"
```

A query type that is not an object type fails with `the query type must be an object type`.

## Arrays and repeated keys

An array item is read from repeated keys, and each value is converted on its own:

```bash
curl "localhost:3000/users/search?ids=01a146da-b664-72d8-b074-72ee9018fcb1&ids=01a146da-b663-7212-b0d6-71457d2a433b"
```

```json
{"data":[{"id":"01a146da-b663-7212-b0d6-71457d2a433b","name":"Ana","email":"ana@acme.com"},{"id":"01a146da-b664-72d8-b074-72ee9018fcb1","name":"Cid","email":"cid@globex.com"}],"total":2}
```

Repeating the key of a single-value item is an error:

```bash
curl "localhost:3000/users/search?q=an&q=bo"
```

```json
{"error":{"code":"VALIDATION_ERROR","message":"Invalid query","details":[{"field":"q","message":"Parameter is repeated"}]}}
```

## Required and optional items

An optional item (`q?: string`) that is not sent is left out of `req.queryItems`. A required item that is missing fails with `Is required`:

```ts check title="endpoints/users/by-email/get.ts"
import type { Endpoint } from "@quickservice/core";

/** @summary Find a user by email */
const handler: Endpoint<{ email: string }> = (repos, req) =>
  repos.users.where((u) => u.email.eq(req.queryItems.email)).select("name", "email", "role").first();

export default handler;
```

```bash
curl localhost:3000/users/by-email
```

```json
{"error":{"code":"VALIDATION_ERROR","message":"Invalid query","details":[{"field":"email","message":"Is required"}]}}
```

```bash
curl "localhost:3000/users/by-email?email=bob@acme.com"
```

```json
{"id":"01a146da-b664-72d7-aa2f-7cbd66be8970","name":"Bob","email":"bob@acme.com","role":"member"}
```

## Unknown keys

Keys that are not declared items are ignored: they do not fail the request and are not in `req.queryItems`. They stay readable through `req.query`, which is always the raw `URLSearchParams`, so `req.query.get("utm_source")` still works here:

```bash
curl "localhost:3000/users/search?ids=a&ids=b&utm_source=newsletter"
```

```json
{"data":[],"total":0}
```

## Validation errors

When any item is invalid, the endpoint answers 400 `VALIDATION_ERROR` with the message `Invalid query` and one entry in `details` per problem, in the order the items are declared. The check runs after the pre-hooks and before the handler, so an `@authorized` hook still rejects an anonymous caller first.

```bash
curl "localhost:3000/users/search?limit=abc&active=yes&role=owner&since=yesterday"
```

```json
{"error":{"code":"VALIDATION_ERROR","message":"Invalid query","details":[{"field":"role","message":"Must be one of: member, admin"},{"field":"active","message":"Must be true or false"},{"field":"since","message":"Must be an ISO 8601 date"},{"field":"limit","message":"Must be a number"}]}}
```

## Defaults and limits

Five JSDoc tags work on query items:

| Tag | Applies to | Effect |
| --- | --- | --- |
| `@default <value>` | any item | Used when the item is absent, so it is always in `req.queryItems`. Strings in single quotes (`'name'`), numbers and booleans as written, dates as ISO strings (`'2026-01-01'`), arrays as JSON (`["a","b"]`). |
| `@min <n>` / `@max <n>` | numbers | `Must be at least <n>` / `Must be at most <n>` |
| `@minLength <n>` / `@maxLength <n>` | strings | `Must be at least <n> characters` / `Must be at most <n> characters` |

In the search endpoint, `limit` is 20 when the client sends none, and the limits apply after conversion:

```bash
curl "localhost:3000/users/search?limit=500&q=a"
```

```json
{"error":{"code":"VALIDATION_ERROR","message":"Invalid query","details":[{"field":"q","message":"Must be at least 2 characters"},{"field":"limit","message":"Must be at most 100"}]}}
```

:::tip
A defaulted item is always present at runtime, but its property is still optional in the type (`limit?: number`). Pass it on as it is, like `page({ limit })` above, or write `limit ?? 20` if you need a plain `number`.
:::

A tag that does not fit the item fails the build, and so does any other tag:

```text
endpoints/users/search/get.ts: query item "q" has invalid @min: only applies to number items
endpoints/users/search/get.ts: query item "limit" has invalid @default: "20" does not match the item type
```

## Query items in the API docs

Each item is listed as an `in: query` parameter of the operation. It is `required` when it is not optional and has no `@default`, and its schema carries `default`, `minimum`, `maximum`, `minLength` and `maxLength` from the tags. Arrays use `style: form` and `explode: true`, and named enums and aliases reference their shared schema.

```bash
curl -s localhost:3000/openapi.json | jq '.paths["/users/search"].get.parameters'
```

```json
[
  { "name": "q", "in": "query", "required": false, "schema": { "type": "string", "minLength": 2, "maxLength": 50 } },
  { "name": "role", "in": "query", "required": false, "schema": { "type": "string", "enum": ["member", "admin"] } },
  { "name": "active", "in": "query", "required": false, "schema": { "type": "boolean" } },
  { "name": "since", "in": "query", "required": false, "schema": { "type": "string", "format": "date-time" } },
  { "name": "ids", "in": "query", "required": false, "style": "form", "explode": true, "schema": { "type": "array", "items": { "type": "string" } } },
  { "name": "limit", "in": "query", "required": false, "schema": { "type": "number", "minimum": 1, "maximum": 100, "default": 20 } }
]
```

When an override of a generated list or read route (for example `endpoints/users/get.ts`) declares a query type, the docs list its items instead of the generated `limit`, `offset`, `sort`, `where`, `fields`, `exclude` and `populate` parameters. Without a query type, the override documents only its path parameters, since the generated query parameters do not apply to a custom handler.
