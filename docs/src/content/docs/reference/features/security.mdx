Safe defaults for every service: security headers, CORS, request limits, timeouts, load shedding, rate limits, IP lists and log masking, each a switchable item.

## Enabling

Turn it on in `quickservice.config.ts`:

```ts
security: {}
```

It is enabled by default; turn it off with `security: false` or `QS_SECURITY_ENABLED=false`.

## Options

| Key | Type | Default | Environment variable | Per request | Description |
| --- | --- | --- | --- | --- | --- |
| `security.proxy.enabled` | `boolean` | `true` | `QS_SECURITY_PROXY_ENABLED` | no | Resolves the client address in req.ip through the proxies the project trusts. Turns it off when false. |
| `security.headers.enabled` | `boolean` | `true` | `QS_SECURITY_HEADERS_ENABLED` | no | Sends the standard security headers on every response. Turns it off when false. |
| `security.files.enabled` | `boolean` | `true` | `QS_SECURITY_FILES_ENABLED` | no | Sends headers on served files that keep a browser from running them as pages of the service. Turns it off when false. |
| `security.cors.enabled` | `boolean` | `true` | `QS_SECURITY_CORS_ENABLED` | no | Answers cross-origin requests and preflights of the allowed origins. Turns it off when false. |
| `security.limits.enabled` | `boolean` | `true` | `QS_SECURITY_LIMITS_ENABLED` | no | Refuses oversized URLs, headers and bodies before reading them. Turns it off when false. |
| `security.timeouts.enabled` | `boolean` | `true` | `QS_SECURITY_TIMEOUTS_ENABLED` | no | Closes idle connections and requests whose body arrives too slowly. Turns it off when false. |
| `security.loadShedding.enabled` | `boolean` | `true` | `QS_SECURITY_LOAD_SHEDDING_ENABLED` | no | Refuses new requests with 503 while a worker has too many in flight. Turns it off when false. |
| `security.rateLimit.enabled` | `boolean` | `true` | `QS_SECURITY_RATE_LIMIT_ENABLED` | no | Limits how many requests each client makes in a time window, answering 429. Turns it off when false. |
| `security.ip.enabled` | `boolean` | `true` | `QS_SECURITY_IP_ENABLED` | no | Accepts or refuses requests by client address. Turns it off when false. |
| `security.masking.enabled` | `boolean` | `true` | `QS_SECURITY_MASKING_ENABLED` | no | Keeps secret values and sensitive fields out of logs and error responses. Turns it off when false. |
| `security.enabled` | `boolean` | `true` | `QS_SECURITY_ENABLED` | no | Turns the feature off when false. |

## Feature API

Other features reach it with `ctx.feature("security")` in their setup, listing `security` in `requires` or `after`.

### `exempt`

```ts
exempt(pattern: string, items: readonly ExemptibleItem[]): void;
```

Exempts the paths matching `pattern` (a path, or a path ending in `/*` for it and every path below it) from the
listed items: `"rateLimit"`, `"loadShedding"`, `"ip"`, `"cors"`, `"headers"` or `"all"`. Only available during setup.
