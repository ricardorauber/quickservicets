Every entity already gets six CRUD routes. When you need something else (a report, an action, a shortcut), add a file to `endpoints/`. Its folder is the route path and its file name is the HTTP method. The same file can also replace a generated route.

The samples on this page use these entities:

```ts check title="entities/User.ts"
export type User = {
  /** @unique @format email */
  email: string;
  name: string;
  /** @default 'member' */
  role: "member" | "admin";
};
```

```ts check title="entities/Organization.ts"
import type { User } from "./User";

/** @authorized:create,update,replace,delete admin */
export type Organization = {
  name: string;
  /** @unique */
  slug: string;
  plan: "free" | "pro";
  members: User[];
  owner?: User;
};
```

```ts check title="entities/Project.ts"
import type { Organization } from "./Organization";

export type Project = {
  name: string;
  organization: Organization;
};
```

`@authorized` is a hook, explained in [Hooks](/guides/hooks/). From these entities the build writes typed repositories to `.generated/types.ts`, so `repos.organizations` and the other repositories are typed in every endpoint.

## Where endpoint files go

Paths work like Next.js routes: each folder is a path segment, a folder in brackets is a path parameter, and the file name is the method.

```text
endpoints/
├── health/
│   └── get.ts                      GET    /health
├── organizations/
│   ├── post.ts                     POST   /organizations         (replaces the generated route)
│   └── [orgId]/
│       ├── stats/
│       │   └── get.ts              GET    /organizations/:orgId/stats
│       └── members/
│           ├── post.ts             POST   /organizations/:orgId/members
│           └── [userId]/
│               └── delete.ts       DELETE /organizations/:orgId/members/:userId
└── users/
    └── me/
        └── get.ts                  GET    /users/me
```

The build checks these rules and fails with a message naming the file:

- File names are `get.ts`, `post.ts`, `put.ts`, `patch.ts`, `delete.ts` or `options.ts`. Any other `.ts` file fails, for example `endpoints/health/index.ts: endpoint files must be named get, post, put, patch, delete, options (with .ts)`. An `options.ts` endpoint answers the CORS preflights of its path itself.
- Static segments use only lowercase letters, digits, `-` and `.`, so `endpoints/Reports` fails with `path segments may only contain a-z, 0-9, "-" and "."`. Use `reports` or `monthly-reports`.
- Parameter names match `^[a-zA-Z_][a-zA-Z0-9_]*$`, for example `[orgId]`.
- Folders side by side must use the same parameter name: `organizations/[id]` next to `organizations/[orgId]` fails with `sibling dynamic segments must use the same name`.
- Catch-all segments such as `[...slug]` are not supported.
- `GET /docs` and `GET /openapi.json` are reserved for the API docs.

When a static segment and a parameter both match, the static one wins: `GET /users/me` reaches `endpoints/users/me/get.ts`, and `GET /users/123` still reaches the generated read route `GET /users/:id`.

## Writing a handler

An endpoint file default-exports a function that receives the repositories, the request and the response controls, and returns the response body. Type it as `Endpoint<Body, Result>` so `req.json()` and the return value are typed and documented.

```ts check title="endpoints/health/get.ts"
import type { Endpoint } from "@quickservice/core";

/** @summary Health check */
const handler: Endpoint<unknown, { status: string }> = () => ({ status: "ok" });

export default handler;
```

```bash
curl localhost:3000/health
```

```json
{"status":"ok"}
```

A handler can be async and use any repository. Path parameters are in `req.params`, named after the folders:

```ts check title="endpoints/organizations/[orgId]/stats/get.ts"
import { HttpError, type Endpoint } from "@quickservice/core";

type Stats = { members: number; projects: number; createdAt: Date };

/**
 * @summary Organization stats
 * @description Counts the members and projects of an organization.
 */
const handler: Endpoint<unknown, Stats> = async (repos, req) => {
  const orgId = req.params.orgId!;
  const organization = await repos.organizations.findById(orgId);
  if (!organization) throw new HttpError(404, "Organization not found");
  const projects = await repos.projects.where((p) => p.organization.eq(orgId)).count();
  return { members: organization.members.length, projects, createdAt: organization.createdAt };
};

export default handler;
```

```bash
curl localhost:3000/organizations/01a146de-9a16-73c6-bb2c-6063dfca5276/stats
```

```json
{"members":1,"projects":1,"createdAt":"2026-10-16T22:39:15.990Z"}
```

`Date` values are sent as ISO 8601 strings. `repos.projects.where(...)` is a fluent query; see [Fluent repository queries](/guides/queries/).

## The request: `req`

| Property | What it holds |
| --- | --- |
| `req.params` | Path parameters, decoded: `{ orgId: "..." }`. |
| `req.query` | The raw query string as `URLSearchParams` (`get`, `getAll`, `has`). Values are strings. |
| `req.queryItems` | Typed, validated query items of a GET or DELETE endpoint; see [Typed query items](/guides/query-items/). `{}` when the endpoint declares none. |
| `req.headers` | The request headers (`Headers`). |
| `req.json()` | The parsed JSON body, typed as `Body`. It is parsed once and cached, so hooks and the handler can both call it. |
| `req.context` | An object shared by the hooks and the handler of one request, empty at the start. Hooks use it to pass the signed-in user, for example. |
| `req.raw` | The native `Request`, for anything else (form data, streams). |
| `req.id`, `req.method`, `req.path` | The request id (also sent back in the `x-request-id` header), the method and the path. |
| `req.ip` | The client's address: the socket's peer address, or the address forwarding headers give when the peer is a proxy listed in `security.proxy.trust`. `unknown` for a request without a socket. |

## The response: return values and `res`

What the handler returns becomes the response:

| The handler returns | The response |
| --- | --- |
| A value (object, array, string, number) | JSON, status 200, or the one set with `@status` or `res.status` |
| `undefined` | An empty body, status 204, or the one set with `@status` or `res.status` |
| A `Response` | Sent as it is |

`@status <code>` on the endpoint sets its success status, from 200 to 299, both for the response and for the API docs. `res.status(code)` and `res.header(name, value)` change the status and headers for one response, and they chain; a status set with `res.status` wins over `@status`:

```ts check title="endpoints/organizations/[orgId]/members/post.ts"
import { HttpError, type Endpoint } from "@quickservice/core";

type AddMember = { email: string };

/**
 * @summary Add a member by email
 * @status 201
 */
const handler: Endpoint<AddMember, { members: number }> = async (repos, req, res) => {
  const { email } = await req.json();
  const user = await repos.users.where((u) => u.email.eq(email)).firstOrDefault();
  if (!user) throw new HttpError(404, "User not found", { details: [{ field: "email", message: "No user has this email" }] });
  const organization = await repos.organizations.update(req.params.orgId!, { members: { add: [user.id] } });
  res.header("location", `/organizations/${organization.id}/members/${user.id}`);
  return { members: organization.members.length };
};

export default handler;
```

```bash
curl -i -X POST localhost:3000/organizations/01a146de-9a16-73c6-bb2c-6063dfca5276/members \
  -H "content-type: application/json" -d '{"email":"bob@acme.com"}'
```

```http
HTTP/1.1 201 Created
location: /organizations/01a146de-9a16-73c6-bb2c-6063dfca5276/members/01a146de-9a14-7790-9f0f-4217ff2256ec

{"members":2}
```

A handler that returns nothing answers 204:

```ts check title="endpoints/organizations/[orgId]/members/[userId]/delete.ts"
import type { Endpoint } from "@quickservice/core";

/** @summary Remove a member */
const handler: Endpoint = async (repos, req) => {
  await repos.organizations.update(req.params.orgId!, { members: { remove: [req.params.userId!] } });
};

export default handler;
```

```bash
curl -i -X DELETE localhost:3000/organizations/01a146de-9a16-73c6-bb2c-6063dfca5276/members/01a146de-9a14-7790-9f0f-4217ff2256ec
```

```http
HTTP/1.1 204 No Content
```

## Errors

Throw `HttpError(status, message, options?)` to answer with the standard error body. The `code` comes from the status (`404` is `NOT_FOUND`, `403` is `FORBIDDEN`), and `options.details` is sent as `details`:

```bash
curl -X POST localhost:3000/organizations/01a146de-9a16-73c6-bb2c-6063dfca5276/members \
  -H "content-type: application/json" -d '{"email":"nope@acme.com"}'
```

```json
{"error":{"code":"NOT_FOUND","message":"User not found","details":[{"field":"email","message":"No user has this email"}]}}
```

Errors thrown by repositories (validation, conflicts, missing records) reach the client the same way. Some errors come from the framework itself:

```bash
curl -X POST localhost:3000/organizations/01a146de-9a16-73c6-bb2c-6063dfca5276/members \
  -H "content-type: application/json" -d '{bad json'
```

```json
{"error":{"code":"VALIDATION_ERROR","message":"Invalid JSON body"}}
```

```bash
curl -i -X PATCH localhost:3000/health
```

```http
HTTP/1.1 405 Method Not Allowed
allow: GET

{"error":{"code":"METHOD_NOT_ALLOWED","message":"Method not allowed"}}
```

Any other thrown error becomes a 500 `Internal server error`; outside production, `details.stack` has the stack trace. The [Errors reference](/reference/errors/) lists every code and message.

## Overriding a generated route

A file with the same method and path as a generated route replaces it, and the other generated routes stay. Here `endpoints/organizations/post.ts` replaces `POST /organizations` so that the caller becomes the owner:

```ts check title="endpoints/organizations/post.ts"
import type { Endpoint } from "@quickservice/core";
import type { OrganizationCreate, User } from "../../.generated/types";

/**
 * @summary Create an organization owned by the caller
 * @description The caller becomes the owner and the first member.
 */
const handler: Endpoint = async (repos, req, res) => {
  const user = req.context.user as User;
  const body = (await req.json()) as OrganizationCreate;
  const organization = await repos.organizations.create({ ...body, owner: user.id, members: [user.id] });
  res.status(201);
  return organization;
};

export default handler;
```

The handler has no generics on purpose: that way the API docs keep the generated route's request body and responses (see [Documenting endpoints](#documenting-endpoints)). By default an override also keeps the entity's hooks for that operation, so the `@authorized:create admin` tag on `Organization` still runs first and sets `req.context.user`:

```bash
curl -X POST localhost:3000/organizations -H "authorization: Bearer bob-token" \
  -H "content-type: application/json" -d '{"name":"Acme","slug":"acme","plan":"pro"}'
```

```json
{"error":{"code":"FORBIDDEN","message":"Requires role: admin"}}
```

```bash
curl -X POST localhost:3000/organizations -H "authorization: Bearer ana-token" \
  -H "content-type: application/json" -d '{"name":"Acme","slug":"acme","plan":"pro"}'
```

```json
{"name":"Acme","slug":"acme","plan":"pro","members":["01a146de-9a13-7231-a40f-4048a78cde08"],"owner":"01a146de-9a13-7231-a40f-4048a78cde08","id":"01a146de-9a16-73c6-bb2c-6063dfca5276","createdAt":"2026-10-16T22:39:15.990Z","updatedAt":"2026-10-16T22:39:15.990Z"}
```

To drop the entity's hooks on overrides, tag the entity with `@overrideHooks replace`; see [Hooks](/guides/hooks/#hooks-on-overridden-routes).

- The parameter folder of an override can have any name, but it must match its siblings: next to `organizations/[orgId]/stats`, override the read route as `organizations/[orgId]/get.ts`.
- `@fields` and `@exclude` choose the fields a custom endpoint sends, and on overrides of list and read routes `@populate` populates references; see [Endpoint tags](/reference/tags/#endpoint-tags).

## Documenting endpoints

Custom endpoints appear in the API docs at `/docs` and in `/openapi.json`:

- `@summary` (one line) and `@description` (may span lines) set the operation's texts. They are not hooks.
- `Body` becomes the request body schema and `Result` the success response schema. Entity types, from `entities/` or from `.generated/types.ts`, become references to their schemas, and `<Entity>Create` and `<Entity>Update` from `.generated/types.ts` to the request body schemas of the generated routes, alone, in arrays or inside object types. `@hidden` fields stay out of these schemas.
- Each path parameter is a required string, and the path uses OpenAPI syntax (`/organizations/{orgId}`).
- The tag is the first path segment and the `operationId` is the method plus the path in PascalCase.
- The documented success status is the `@status` code, with the `Result` schema (`@status 204` has no content). Without `@status` it is 200, or 204 for a `delete` without a `Result` type; `res.status` is not read by the docs, so declare the status with `@status` to document it.
- An override without generics keeps the generated route's schemas and responses; generics, `@summary` and `@description` take precedence when present. Its documented parameters are its path parameters plus the items of its query type, never the generated `limit`, `offset`, `sort`, `where`, `fields`, `exclude` or `populate`.

```bash
curl -s localhost:3000/openapi.json | jq '.paths["/organizations/{orgId}/stats"].get'
```

```json
{
  "tags": ["organizations"],
  "operationId": "getOrganizationsOrgIdStats",
  "parameters": [{ "name": "orgId", "in": "path", "required": true, "schema": { "type": "string" } }],
  "responses": {
    "200": {
      "description": "Success",
      "content": {
        "application/json": {
          "schema": {
            "type": "object",
            "properties": {
              "members": { "type": "number" },
              "projects": { "type": "number" },
              "createdAt": { "type": "string", "format": "date-time" }
            },
            "required": ["members", "projects", "createdAt"]
          }
        }
      }
    }
  },
  "summary": "Organization stats",
  "description": "Counts the members and projects of an organization."
}
```
