Endpoints e hooks recebem `repos`, com um repositório por entidade (`repos.users`, ou `repos.<schema>.<coleção>`).

## Repository

`Repository<T, R, C, U>`: `T` é o registro, `R` suas referências, `C` e `U` as entradas de criação e atualização.

### `create`

```ts
create(data: C, options?: ReadOptions): Promise<T>;
```

Valida e grava um registro novo (aplicando defaults e checando referências) e o devolve.

### `findById`

```ts
findById<const P extends readonly PopulatePath<R>[] = []>(id: string, options?: PopulateOptions<P>): Promise<Populated<T, R, P[number]> | null>;
```

O registro com esse id, ou null; `populate` troca caminhos de referência pelos registros.

### `findOne`

```ts
findOne<const P extends readonly PopulatePath<R>[] = []>(where: Condition[], options?: PopulateOptions<P>): Promise<Populated<T, R, P[number]> | null>;
```

O primeiro registro que atende a todas as condições, ou null.

### `list`

```ts
list<const P extends readonly PopulatePath<R>[] = []>(query: ListQuery, options?: PopulateOptions<P>): Promise<ListResult<Populated<T, R, P[number]>>>;
```

Uma página de registros para condições, ordenação, limit e offset explícitos, com o total.

### `findByIds`

```ts
findByIds<const P extends readonly PopulatePath<R>[] = []>(ids: readonly string[], options?: { include?: P }): Promise<Populated<T, R, P[number]>[]>;
```

Os registros dos `ids` nessa ordem, pulando ids sem registro e sem repetir; `include` popula como o `populate`.

### `update`

```ts
update(id: string, changes: U, options?: ReadOptions): Promise<T>;
```

Aplica uma mudança parcial (reference arrays também aceitam `{ add, remove }`) e devolve o registro.

### `replace`

```ts
replace(id: string, data: C, options?: ReadOptions): Promise<T>;
```

Substitui todos os campos graváveis e devolve o registro.

### `delete`

```ts
delete(id: string): Promise<void>;
```

Apaga o registro, aplicando as regras `@onDelete` dos registros que o referenciam.

### `populate`

```ts
populate(records: T[], paths: readonly string[]): Promise<T[]>;
```

Popula caminhos de referência em registros já carregados, por exemplo resultados de um endpoint customizado.

### `createWith`

```ts
createWith(id: string, managed: Record<string, unknown>, data: unknown): Promise<T>;
```

Cria um registro cujos campos gerenciados pelo framework (como os metadados de um arquivo) e id já são conhecidos.

### `replaceWith`

```ts
replaceWith(id: string, managed: Record<string, unknown>, data: unknown): Promise<T>;
```

Substitui um registro como o `replace`, também definindo campos gerenciados pelo framework.

### `where`

```ts
where(lambda: QueryLambda<T>): Query<T, R>;
```

Uma consulta fluente filtrada pelas condições da lambda.

### `query`

```ts
query(): Query<T, R>;
```

Uma consulta fluente sobre todos os registros.

## Query

Devolvida por `where` e `query`; todo método, menos os finais, devolve uma consulta nova.

### `where`

```ts
where(lambda: QueryLambda<T>): Query<T, R>;
```

Restringe a consulta com as condições da lambda (AND com as chamadas anteriores).

### `orderBy`

```ts
orderBy(lambda: SortLambda<T>): Query<T, R>;
```

Ordena por um campo, substituindo a ordenação anterior.

### `orderByDescending`

```ts
orderByDescending(lambda: SortLambda<T>): Query<T, R>;
```

Ordena por um campo em ordem decrescente, substituindo a ordenação anterior.

### `thenBy`

```ts
thenBy(lambda: SortLambda<T>): Query<T, R>;
```

Acrescenta mais um campo de ordenação.

### `thenByDescending`

```ts
thenByDescending(lambda: SortLambda<T>): Query<T, R>;
```

Acrescenta mais um campo de ordenação, em ordem decrescente.

### `skip`

```ts
skip(count: number): Query<T, R>;
```

Pula os primeiros `count` resultados (não vale para `count()` e `any()`).

### `take`

```ts
take(count: number): Query<T, R>;
```

Devolve no máximo `count` resultados (não vale para `count()` e `any()`).

### `select`

```ts
select<K extends keyof T & string>(...fields: K[]): Query<Pick<T, K | ("id" & keyof T)>, R>;
```

Devolve só esses campos, mais o `id`.

### `include`

```ts
include<const P extends readonly PopulatePath<R>[]>(...paths: P): Query<Populated<T, R, P[number]>>;
```

Troca caminhos de referência pelos registros referenciados, por exemplo `include("profiles.permissions.module")`.

### `all`

```ts
all(): Promise<T[]>;
```

Todos os resultados; falha quando passam de `repositories.findAllMax`.

### `first`

```ts
first(): Promise<T>;
```

O primeiro resultado, ou 404 `<Entity> not found`.

### `firstOrDefault`

```ts
firstOrDefault(): Promise<T | null>;
```

O primeiro resultado, ou null.

### `count`

```ts
count(): Promise<number>;
```

O número de resultados, sem carregar registros.

### `any`

```ts
any(): Promise<boolean>;
```

Se pelo menos um registro atende, sem carregar registros.

### `page`

```ts
page(options?: PageOptions): Promise<{ data: T[]; total: number; limit: number; offset: number }>;
```

`{ data, total, limit, offset }`, como as rotas de listagem geradas.
