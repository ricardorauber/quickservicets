# 0066 - The project skill keeps its frontmatter first, with the generated header right after it

- Date: 2026-10-26
- Spec: 0836-init-agent-files
- Status: accepted

## Context
Spec 0836 R2 asks `init` to mark every generated agent file with the first-line comment
`<!-- generated by quickservicets; edit below the marker to keep your changes -->`. A Claude Code `SKILL.md` must start
with its YAML frontmatter (`---` on the first line), or Claude Code does not read the skill's name and description and
never loads it. A comment on the first line of `.claude/skills/quickservicets/SKILL.md` would break the skill.

## Options considered
- A: Put the comment first in every file except `SKILL.md`, where it goes on the line right after the frontmatter; the
  generated part still ends at `<!-- quickservicets:end -->`, and `agents update` rewrites everything up to it,
  frontmatter included — the skill keeps working and is still marked.
- B: Put the comment on the first line of `SKILL.md` too — follows the wording, but Claude Code ignores the skill.
- C: Leave `SKILL.md` without the comment — the skill works, but the file does not say it is generated.

## Decision
The user asked to follow the recommended option for every open decision automatically; option A was recommended.

## Consequences
`packages/cli/src/agents/project.ts` places the header after a frontmatter block when the file has one. The spec could
say "the first line, or the line after the frontmatter".
