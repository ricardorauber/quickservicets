Toda entidade já ganha seis rotas CRUD. Quando você precisa de algo diferente (um relatório, uma ação, um atalho), adicione um arquivo em `endpoints/`. A pasta dele é o caminho da rota e o nome do arquivo é o método HTTP. O mesmo arquivo também pode substituir uma rota gerada.

Os exemplos desta página usam estas entidades:

```ts check title="entities/User.ts"
export type User = {
  /** @unique @format email */
  email: string;
  name: string;
  /** @default 'member' */
  role: "member" | "admin";
};
```

```ts check title="entities/Organization.ts"
import type { User } from "./User";

/** @authorized:create,update,replace,delete admin */
export type Organization = {
  name: string;
  /** @unique */
  slug: string;
  plan: "free" | "pro";
  members: User[];
  owner?: User;
};
```

```ts check title="entities/Project.ts"
import type { Organization } from "./Organization";

export type Project = {
  name: string;
  organization: Organization;
};
```

`@authorized` é um hook, explicado em [Hooks](/pt-br/guides/hooks/). A partir dessas entidades, o build escreve repositórios tipados em `.generated/types.ts`, então `repos.organizations` e os outros repositórios são tipados em todo endpoint.

## Onde ficam os arquivos de endpoint

Os caminhos funcionam como as rotas do Next.js: cada pasta é um segmento do caminho, uma pasta entre colchetes é um parâmetro de caminho, e o nome do arquivo é o método.

```text
endpoints/
├── health/
│   └── get.ts                      GET    /health
├── organizations/
│   ├── post.ts                     POST   /organizations         (replaces the generated route)
│   └── [orgId]/
│       ├── stats/
│       │   └── get.ts              GET    /organizations/:orgId/stats
│       └── members/
│           ├── post.ts             POST   /organizations/:orgId/members
│           └── [userId]/
│               └── delete.ts       DELETE /organizations/:orgId/members/:userId
└── users/
    └── me/
        └── get.ts                  GET    /users/me
```

O build verifica estas regras e falha com uma mensagem que cita o arquivo:

- Os nomes de arquivo são `get.ts`, `post.ts`, `put.ts`, `patch.ts` ou `delete.ts`. Qualquer outro arquivo `.ts` falha, por exemplo `endpoints/health/index.ts: endpoint files must be named get, post, put, patch, delete (with .ts)`.
- Segmentos estáticos usam só letras minúsculas, dígitos, `-` e `.`, então `endpoints/Reports` falha com `path segments may only contain a-z, 0-9, "-" and "."`. Use `reports` ou `monthly-reports`.
- Nomes de parâmetro seguem `^[a-zA-Z_][a-zA-Z0-9_]*$`, por exemplo `[orgId]`.
- Pastas lado a lado precisam usar o mesmo nome de parâmetro: `organizations/[id]` ao lado de `organizations/[orgId]` falha com `sibling dynamic segments must use the same name`.
- Segmentos catch-all como `[...slug]` não são suportados.
- `GET /docs` e `GET /openapi.json` são reservados para a documentação da API.

Quando um segmento estático e um parâmetro casam com o caminho, o estático vence: `GET /users/me` chega em `endpoints/users/me/get.ts`, e `GET /users/123` continua chegando na rota de leitura gerada `GET /users/:id`.

## Escrevendo um handler

Um arquivo de endpoint exporta por padrão uma função que recebe os repositórios, a requisição e os controles da resposta, e retorna o corpo da resposta. Tipe-a como `Endpoint<Body, Result>` para que `req.json()` e o valor de retorno fiquem tipados e documentados.

```ts check title="endpoints/health/get.ts"
import type { Endpoint } from "@quickservice/core";

/** @summary Health check */
const handler: Endpoint<unknown, { status: string }> = () => ({ status: "ok" });

export default handler;
```

```bash
curl localhost:3000/health
```

```json
{"status":"ok"}
```

Um handler pode ser assíncrono e usar qualquer repositório. Os parâmetros de caminho ficam em `req.params`, com o nome das pastas:

```ts check title="endpoints/organizations/[orgId]/stats/get.ts"
import { HttpError, type Endpoint } from "@quickservice/core";

type Stats = { members: number; projects: number; createdAt: Date };

/**
 * @summary Organization stats
 * @description Counts the members and projects of an organization.
 */
const handler: Endpoint<unknown, Stats> = async (repos, req) => {
  const orgId = req.params.orgId!;
  const organization = await repos.organizations.findById(orgId);
  if (!organization) throw new HttpError(404, "Organization not found");
  const projects = await repos.projects.where((p) => p.organization.eq(orgId)).count();
  return { members: organization.members.length, projects, createdAt: organization.createdAt };
};

export default handler;
```

```bash
curl localhost:3000/organizations/01a146de-9a16-73c6-bb2c-6063dfca5276/stats
```

```json
{"members":1,"projects":1,"createdAt":"2026-10-16T22:39:15.990Z"}
```

Valores `Date` são enviados como strings ISO 8601. `repos.projects.where(...)` é uma consulta fluente; veja [Consultas fluentes nos repositórios](/pt-br/guides/queries/).

## A requisição: `req`

| Propriedade | O que contém |
| --- | --- |
| `req.params` | Os parâmetros de caminho, decodificados: `{ orgId: "..." }`. |
| `req.query` | A query string crua como `URLSearchParams` (`get`, `getAll`, `has`). Os valores são strings. |
| `req.queryItems` | Os query items tipados e validados de um endpoint GET ou DELETE; veja [Query items tipados](/pt-br/guides/query-items/). `{}` quando o endpoint não declara nenhum. |
| `req.headers` | Os headers da requisição (`Headers`). |
| `req.json()` | O corpo JSON já interpretado, tipado como `Body`. Ele é lido uma vez e guardado, então hooks e handler podem chamá-lo. |
| `req.context` | Um objeto compartilhado pelos hooks e pelo handler de uma requisição, vazio no início. Hooks o usam para passar o usuário autenticado, por exemplo. |
| `req.raw` | O `Request` nativo, para todo o resto (form data, streams). |
| `req.id`, `req.method`, `req.path` | O id da requisição (também devolvido no header `x-request-id`), o método e o caminho. |

## A resposta: valores de retorno e `res`

O que o handler retorna vira a resposta:

| O handler retorna | A resposta |
| --- | --- |
| Um valor (objeto, array, string, número) | JSON, status 200 ou o definido com `res.status` |
| `undefined` | Corpo vazio, status 204 ou o definido com `res.status` |
| Um `Response` | Enviado como está |

`res.status(code)` e `res.header(name, value)` mudam o status e os headers, e podem ser encadeados:

```ts check title="endpoints/organizations/[orgId]/members/post.ts"
import { HttpError, type Endpoint } from "@quickservice/core";

type AddMember = { email: string };

/** @summary Add a member by email */
const handler: Endpoint<AddMember, { members: number }> = async (repos, req, res) => {
  const { email } = await req.json();
  const user = await repos.users.where((u) => u.email.eq(email)).firstOrDefault();
  if (!user) throw new HttpError(404, "User not found", { details: [{ field: "email", message: "No user has this email" }] });
  const organization = await repos.organizations.update(req.params.orgId!, { members: { add: [user.id] } });
  res.status(201).header("location", `/organizations/${organization.id}/members/${user.id}`);
  return { members: organization.members.length };
};

export default handler;
```

```bash
curl -i -X POST localhost:3000/organizations/01a146de-9a16-73c6-bb2c-6063dfca5276/members \
  -H "content-type: application/json" -d '{"email":"bob@acme.com"}'
```

```http
HTTP/1.1 201 Created
location: /organizations/01a146de-9a16-73c6-bb2c-6063dfca5276/members/01a146de-9a14-7790-9f0f-4217ff2256ec

{"members":2}
```

Um handler que não retorna nada responde 204:

```ts check title="endpoints/organizations/[orgId]/members/[userId]/delete.ts"
import type { Endpoint } from "@quickservice/core";

/** @summary Remove a member */
const handler: Endpoint = async (repos, req) => {
  await repos.organizations.update(req.params.orgId!, { members: { remove: [req.params.userId!] } });
};

export default handler;
```

```bash
curl -i -X DELETE localhost:3000/organizations/01a146de-9a16-73c6-bb2c-6063dfca5276/members/01a146de-9a14-7790-9f0f-4217ff2256ec
```

```http
HTTP/1.1 204 No Content
```

## Erros

Lance `HttpError(status, message, options?)` para responder com o corpo de erro padrão. O `code` vem do status (`404` é `NOT_FOUND`, `403` é `FORBIDDEN`), e `options.details` é enviado como `details`:

```bash
curl -X POST localhost:3000/organizations/01a146de-9a16-73c6-bb2c-6063dfca5276/members \
  -H "content-type: application/json" -d '{"email":"nope@acme.com"}'
```

```json
{"error":{"code":"NOT_FOUND","message":"User not found","details":[{"field":"email","message":"No user has this email"}]}}
```

Erros lançados pelos repositórios (validação, conflitos, registros inexistentes) chegam ao cliente do mesmo jeito. Alguns erros vêm do próprio framework:

```bash
curl -X POST localhost:3000/organizations/01a146de-9a16-73c6-bb2c-6063dfca5276/members \
  -H "content-type: application/json" -d '{bad json'
```

```json
{"error":{"code":"VALIDATION_ERROR","message":"Invalid JSON body"}}
```

```bash
curl -i -X PATCH localhost:3000/health
```

```http
HTTP/1.1 405 Method Not Allowed
allow: GET

{"error":{"code":"METHOD_NOT_ALLOWED","message":"Method not allowed"}}
```

Qualquer outro erro lançado vira um 500 `Internal server error`; fora de produção, `details.stack` traz o stack trace. A [referência de erros](/pt-br/reference/errors/) lista todos os códigos e mensagens.

## Substituindo uma rota gerada

Um arquivo com o mesmo método e caminho de uma rota gerada a substitui, e as outras rotas geradas continuam. Aqui `endpoints/organizations/post.ts` substitui `POST /organizations` para que quem chama vire o dono:

```ts check title="endpoints/organizations/post.ts"
import type { Endpoint } from "@quickservice/core";
import type { OrganizationCreate, User } from "../../.generated/types";

/**
 * @summary Create an organization owned by the caller
 * @description The caller becomes the owner and the first member.
 */
const handler: Endpoint = async (repos, req, res) => {
  const user = req.context.user as User;
  const body = (await req.json()) as OrganizationCreate;
  const organization = await repos.organizations.create({ ...body, owner: user.id, members: [user.id] });
  res.status(201);
  return organization;
};

export default handler;
```

O handler não tem genéricos de propósito: assim a documentação da API mantém o corpo da requisição e as respostas da rota gerada (veja [Documentando endpoints](#documentando-endpoints)). Por padrão, uma substituição também mantém os hooks da entidade para aquela operação, então a tag `@authorized:create admin` de `Organization` continua rodando antes e preenche `req.context.user`:

```bash
curl -X POST localhost:3000/organizations -H "authorization: Bearer bob-token" \
  -H "content-type: application/json" -d '{"name":"Acme","slug":"acme","plan":"pro"}'
```

```json
{"error":{"code":"FORBIDDEN","message":"Requires role: admin"}}
```

```bash
curl -X POST localhost:3000/organizations -H "authorization: Bearer ana-token" \
  -H "content-type: application/json" -d '{"name":"Acme","slug":"acme","plan":"pro"}'
```

```json
{"name":"Acme","slug":"acme","plan":"pro","members":["01a146de-9a13-7231-a40f-4048a78cde08"],"owner":"01a146de-9a13-7231-a40f-4048a78cde08","id":"01a146de-9a16-73c6-bb2c-6063dfca5276","createdAt":"2026-10-16T22:39:15.990Z","updatedAt":"2026-10-16T22:39:15.990Z"}
```

Para descartar os hooks da entidade nas substituições, marque a entidade com `@overrideHooks replace`; veja [Hooks](/pt-br/guides/hooks/#hooks-em-rotas-substituídas).

- A pasta de parâmetro de uma substituição pode ter qualquer nome, mas precisa ser igual à das pastas vizinhas: ao lado de `organizations/[orgId]/stats`, substitua a rota de leitura como `organizations/[orgId]/get.ts`.
- `@fields` e `@exclude` escolhem os campos que um endpoint personalizado envia, e nas substituições das rotas de listagem e leitura `@populate` popula referências; veja [Tags de endpoint](/pt-br/reference/tags/#tags-de-endpoint).

## Documentando endpoints

Endpoints personalizados aparecem na documentação da API em `/docs` e em `/openapi.json`:

- `@summary` (uma linha) e `@description` (pode ter várias linhas) definem os textos da operação. Elas não são hooks.
- `Body` vira o schema do corpo da requisição e `Result` o schema da resposta de sucesso. Tipos declarados em `entities/` viram referências aos seus schemas. Um tipo que o build não consegue converter, como os tipos gerados de `.generated/types.ts`, cai para `{ "type": "object" }` com um aviso.
- Cada parâmetro de caminho é uma string obrigatória, e o caminho usa a sintaxe do OpenAPI (`/organizations/{orgId}`).
- A tag é o primeiro segmento do caminho e o `operationId` é o método mais o caminho em PascalCase.
- O status de sucesso documentado é 200, ou 204 para um `delete` sem tipo `Result`, independente do que `res.status` define em tempo de execução.
- Uma substituição sem genéricos mantém os schemas, parâmetros e respostas da rota gerada; genéricos, `@summary` e `@description` têm prioridade quando presentes.

```bash
curl -s localhost:3000/openapi.json | jq '.paths["/organizations/{orgId}/stats"].get'
```

```json
{
  "tags": ["organizations"],
  "operationId": "getOrganizationsOrgIdStats",
  "parameters": [{ "name": "orgId", "in": "path", "required": true, "schema": { "type": "string" } }],
  "responses": {
    "200": {
      "description": "Success",
      "content": {
        "application/json": {
          "schema": {
            "type": "object",
            "properties": {
              "members": { "type": "number" },
              "projects": { "type": "number" },
              "createdAt": { "type": "string", "format": "date-time" }
            },
            "required": ["members", "projects", "createdAt"]
          }
        }
      }
    }
  },
  "summary": "Organization stats",
  "description": "Counts the members and projects of an organization."
}
```
