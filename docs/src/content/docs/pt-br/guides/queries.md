Endpoints e hooks recebem `repos`, com um repositório por entidade. Além de `create`, `findById`, `update` e dos outros métodos de um registro só, todo repositório inicia uma consulta tipada: você filtra com lambdas, encadeia ordenação e paginação e termina com um método terminal como `all()` ou `first()`.

```ts check
import type { Repositories } from "@quickservice/core";

export async function activeAdmins(repos: Repositories) {
  return repos.users
    .where((u) => u.role.eq("admin").and(u.active.eq(true)))
    .orderBy((u) => u.name)
    .all();
}
```

Nomes de campo, operadores e valores são verificados pelo TypeScript, e todo método retorna uma nova consulta, então você pode guardar uma consulta base e estendê-la.

## Os exemplos desta página

Os exemplos usam as entidades `User`, `Organization` (com `members: User[]` e `owner?: User`) e `Project` (com `organization: Organization`), e estes dados:

| Usuário | `role` | `active` | `age` | Organização |
| --- | --- | --- | --- | --- |
| Ana (`ana@acme.com`) | admin | true | 34 | Acme (dona) |
| Bob (`bob@acme.com`) | member | false | 28 | Acme |
| Cid (`cid@globex.com`) | member | true | 41 | Globex |
| Dee (`dee@globex.com`) | admin | true | 25 | Globex |

Os usuários foram criados nessa ordem. Os projetos são Website (Acme) e App (Globex). Comentários como `// ["Dee", "Ana"]` mostram os nomes dos registros que cada consulta retorna.

## Iniciando uma consulta

`where(lambda)` inicia uma consulta filtrada e `query()` inicia uma sobre todos os registros:

```ts check
import type { Repositories } from "@quickservice/core";

export async function starts(repos: Repositories) {
  const admins = await repos.users.where((u) => u.role.eq("admin")).all(); // ["Dee", "Ana"]
  const everyone = await repos.users.query().all(); // ["Dee", "Cid", "Bob", "Ana"]
  return { admins, everyone };
}
```

Sem ordenação, os resultados vêm dos mais novos para os mais antigos (`createdAt` decrescente, depois `id` decrescente). Os registros voltam exatamente como as outras leituras do repositório os retornam: campos `@hidden` removidos, lados derivados de relações e URLs de arquivos preenchidos.

## Condições por tipo de campo

A lambda recebe um handle por campo armazenado, mais `id`, `createdAt` e `updatedAt`. Cada handle oferece os operadores que combinam com seu tipo, os mesmos dos filtros `where` das rotas de listagem geradas:

| Tipo do campo | Operadores |
| --- | --- |
| Todo escalar: string, número, booleano, `Date`, enum, referência única | `eq`, `ne`, `in`, `nin`, `exists`, `isNull` |
| Números e datas | também `gt`, `gte`, `lt`, `lte` |
| Strings (não enums nem uniões) | também `contains`, `startsWith` |
| Arrays de referências (`members: User[]`) | `contains`, `containsAny`, `containsAll`, `isEmpty` |

```ts check
import type { Repositories } from "@quickservice/core";

export async function conditions(repos: Repositories, anaId: string, bobId: string, cidId: string, deeId: string, acmeId: string) {
  // Strings: contains and startsWith ignore case and match the text literally.
  await repos.users.where((u) => u.email.contains("ACME")).all(); // ["Bob", "Ana"]
  await repos.users.where((u) => u.name.startsWith("d")).all(); // ["Dee"]

  // Numbers and dates compare.
  await repos.users.where((u) => u.age.lt(30)).all(); // ["Dee", "Bob"]
  await repos.users.where((u) => u.createdAt.gte(new Date("2026-01-01"))).count(); // 4

  // Lists of values.
  await repos.users.where((u) => u.id.in([anaId, cidId])).all(); // ["Cid", "Ana"]
  await repos.users.where((u) => u.role.nin(["admin"])).all(); // ["Cid", "Bob"]

  // exists() and isNull() mean true; pass false for the opposite.
  await repos.users.where((u) => u.age.isNull()).all(); // []
  await repos.organizations.where((o) => o.owner.exists()).all(); // ["Acme"]

  // A single reference holds an id.
  await repos.projects.where((p) => p.organization.eq(acmeId)).all(); // ["Website"]

  // Reference arrays.
  await repos.organizations.where((o) => o.members.contains(bobId)).all(); // ["Acme"]
  await repos.organizations.where((o) => o.members.containsAny([anaId, deeId])).all(); // ["Globex", "Acme"]
  await repos.organizations.where((o) => o.members.containsAll([cidId, deeId])).all(); // ["Globex"]
  await repos.organizations.where((o) => o.members.isEmpty()).all(); // []
}
```

Erros aparecem na verificação de tipos, em vez de em tempo de execução:

```ts
repos.users.where((u) => u.emial.eq("x")); // Property 'emial' does not exist. Did you mean 'email'?
repos.users.where((u) => u.age.gte("30")); // Argument of type 'string' is not assignable to parameter of type 'number'.
repos.users.where((u) => u.role.contains("adm")); // Property 'contains' does not exist: role is an enum.
```

Objetos, arrays de valores simples e URLs de arquivos calculadas não podem ser filtrados.

## Combinando condições: `and`, `or` e `where` encadeado

Dentro de uma lambda, `.and(...)` e `.or(...)` combinam condições. Elas se aninham do jeito que você as chama: `a.and(b.or(c))` é `a AND (b OR c)`, e `a.or(b).and(c)` é `(a OR b) AND c`. Cada `.where(...)` a mais acrescenta condições com AND.

```ts check
import type { Repositories } from "@quickservice/core";

export async function combined(repos: Repositories) {
  // AND inside one lambda, or across chained where calls: the same result.
  await repos.users.where((u) => u.role.eq("member").and(u.active.eq(true))).all(); // ["Cid"]
  await repos.users.where((u) => u.role.eq("member")).where((u) => u.active.eq(true)).all(); // ["Cid"]

  // OR.
  await repos.users.where((u) => u.role.eq("admin").or(u.email.contains("@globex.com"))).all(); // ["Dee", "Cid", "Ana"]

  // AND with a nested OR: active, and either 30 or older or an admin.
  await repos.users.where((u) => u.active.eq(true).and(u.age.gte(30).or(u.role.eq("admin")))).all(); // ["Dee", "Cid", "Ana"]
}
```

OR funciona em todos os adaptadores de banco, inclusive em condições sobre lados derivados de relações.

## Ordenação: `orderBy`, `orderByDescending`, `thenBy`, `thenByDescending`

`orderBy` e `orderByDescending` definem o primeiro campo de ordenação e substituem qualquer ordenação anterior; `thenBy` e `thenByDescending` acrescentam outros. `id` é sempre o último critério de desempate, então a ordem é estável.

```ts check
import type { Repositories } from "@quickservice/core";

export async function ordered(repos: Repositories) {
  await repos.users.query().orderBy((u) => u.name).all(); // ["Ana", "Bob", "Cid", "Dee"]
  await repos.users.query().orderByDescending((u) => u.age).all(); // ["Cid", "Ana", "Bob", "Dee"]
  await repos.users.query().orderBy((u) => u.role).thenBy((u) => u.name).all(); // ["Ana", "Dee", "Bob", "Cid"]
  await repos.users.query().orderBy((u) => u.role).thenByDescending((u) => u.age).all(); // ["Ana", "Dee", "Cid", "Bob"]
}
```

Você pode ordenar pelos campos que as rotas de listagem aceitam em `sort`: escalares, datas e referências únicas. Arrays de referências e lados derivados de relações não passam na verificação de tipos:

```ts
repos.organizations.query().orderBy((o) => o.members); // Property 'members' does not exist on type 'SortFields<Organization>'.
```

## Fatiando: `skip` e `take`

`skip(n)` pula os primeiros `n` resultados e `take(n)` retorna no máximo `n`. Eles valem para `all()`, `first()`, `firstOrDefault()` e `page()`, mas não para `count()` e `any()`. Um valor negativo ou fracionário lança um erro, por exemplo `skip expects a non-negative integer, got -1`.

```ts check
import type { Repositories } from "@quickservice/core";

export async function sliced(repos: Repositories) {
  const byName = repos.users.query().orderBy((u) => u.name);
  await byName.skip(1).take(2).all(); // ["Bob", "Cid"]
  await byName.skip(1).take(2).count(); // 4
}
```

## Escolhendo campos: `select`

`select(...fields)` retorna só esses campos mais o `id`, e o tipo do resultado é reduzido de acordo:

```ts check
import type { Repositories } from "@quickservice/core";

export async function selected(repos: Repositories) {
  const admins = await repos.users.where((u) => u.role.eq("admin")).orderBy((u) => u.name).select("name", "email").all();
  // [{ id: "...", name: "Ana", email: "ana@acme.com" }, { id: "...", name: "Dee", email: "dee@globex.com" }]
  return admins.map((user) => `${user.name} <${user.email}>`);
}
```

Campos desconhecidos não passam na verificação de tipos, nem os campos que você deixou de fora: depois de `select("name")`, `user.email` é um erro.

## Carregando registros relacionados: `include`

`include(...paths)` troca os ids de referência pelos registros referenciados. Os caminhos podem ter vários níveis (`organization.members`), e o resultado é tipado em todos eles:

```ts check
import type { Repositories } from "@quickservice/core";

export async function included(repos: Repositories) {
  const projects = await repos.projects.query().orderBy((p) => p.name).include("organization").all();
  const pairs = projects.map((project) => [project.name, project.organization?.name]); // [["App", "Globex"], ["Website", "Acme"]]

  const website = await repos.projects.where((p) => p.name.eq("Website")).include("organization.members").first();
  const members = website.organization?.members.map((user) => user.name); // ["Ana", "Bob"]
  return { pairs, members };
}
```

Um caminho que não existe não passa na verificação de tipos:

```ts
repos.projects.query().include("organization.member");
// Argument of type '"organization.member"' is not assignable to parameter of type
// '"organization" | "organization.owner" | "organization.members"'.
```

`include` segue as mesmas regras da opção de leitura `populate`. Um caminho pode ter no máximo `populate.maxDepth` segmentos (2 por padrão); caminhos maiores falham com `Populate depth exceeds 2`. Aumente o limite na [configuração](/pt-br/reference/config/).

Um endpoint pode retornar diretamente um registro com include. Esta substituição da rota de leitura gerada responde com a organização do projeto populada:

```ts check title="endpoints/projects/[id]/get.ts"
import type { Endpoint } from "@quickservice/core";

/** Reads a project with its organization populated. */
const handler: Endpoint = (repos, req) => repos.projects.where((p) => p.id.eq(req.params.id!)).include("organization").first();

export default handler;
```

## Executando a consulta

Uma consulta não faz nada até você chamar um dos seus métodos terminais.

### `all`

Todos os resultados. Para proteger o servidor, `all()` primeiro conta os registros que retornaria (depois de `skip` e `take`) e lança um erro quando há mais que `repositories.findAllMax` (10000 por padrão), sem carregá-los:

```text
Query on User matched 3 records, more than repositories.findAllMax (2)
```

Use `take(n)` ou `page()` em tabelas grandes, ou aumente o limite em `quickservice.config.ts`:

```ts check title="quickservice.config.ts"
import { defineConfig, memoryAdapter } from "@quickservice/core";

export default defineConfig({
  database: memoryAdapter(),
  repositories: { findAllMax: 50_000 },
});
```

### `first` e `firstOrDefault`

`first()` retorna o primeiro resultado ou falha com 404 `<Entity> not found`, que vira a resposta quando lançado em um endpoint (veja `GET /projects/missing` acima). `firstOrDefault()` retorna `null` nesse caso.

```ts check
import type { Repositories } from "@quickservice/core";

export async function firsts(repos: Repositories) {
  const youngest = await repos.users.query().orderBy((u) => u.age).first(); // Dee
  const zoe = await repos.users.where((u) => u.email.eq("zoe@acme.com")).firstOrDefault(); // null
  return { youngest, zoe };
}
```

### `count` e `any`

Os dois rodam sem carregar registros:

```ts check
import type { Repositories } from "@quickservice/core";

export async function counts(repos: Repositories) {
  const active = await repos.users.where((u) => u.active.eq(true)).count(); // 3
  const hasAdmins = await repos.users.where((u) => u.role.eq("admin")).any(); // true
  return { active, hasAdmins };
}
```

### `page`

`page({ limit, offset })` retorna `{ data, total, limit, offset }`, o mesmo formato das rotas de listagem geradas. `limit` vai de 1 a 100 (padrão 20) e `offset` a partir de 0 (padrão 0); outros valores lançam um erro, por exemplo `page limit must be an integer from 1 to 100, got 0`.

```ts check
import type { Repositories } from "@quickservice/core";

export async function paged(repos: Repositories) {
  return repos.users.query().orderBy((u) => u.name).page({ limit: 2, offset: 2 });
  // { data: [Cid, Dee], total: 4, limit: 2, offset: 2 }
}
```

## Carregando muitos registros por id: `findByIds`

`findByIds(ids, { include })` retorna os registros de `ids` na mesma ordem, pulando ids sem registro e sem repetir nenhum. Ele os carrega em lotes, então listas longas não são problema. `include` popula como o `include` de uma consulta.

```ts check
import type { Repositories } from "@quickservice/core";

export async function byIds(repos: Repositories, anaId: string, cidId: string, globexId: string) {
  const users = await repos.users.findByIds([cidId, anaId, "missing", anaId]); // ["Cid", "Ana"]
  const [globex] = await repos.organizations.findByIds([globexId], { include: ["members"] });
  const members = globex?.members.map((user) => user.name); // ["Cid", "Dee"]
  return { users, members };
}
```
