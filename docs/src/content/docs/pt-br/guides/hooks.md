Um hook é um pequeno trecho de código que roda em volta de um handler: um **pre-hook** roda antes dele (para autenticar, verificar permissões, carregar algo em `req.context`), e um **post-hook** roda depois e pode mudar o corpo da resposta. Você escreve cada hook uma vez em `hooks/` e o liga com uma tag JSDoc, em uma entidade para as rotas geradas dela ou em qualquer endpoint personalizado.

## Escrevendo um hook

Cada arquivo em `hooks/` exporta por padrão o resultado de `definePreHook` ou `definePostHook`, e o nome do arquivo é o nome do hook. Este pre-hook confere um token bearer, opcionalmente confere o papel do usuário e guarda o usuário em `req.context` para o handler:

```ts check title="hooks/authorized.ts"
import { definePreHook, HttpError } from "@quickservice/core";

/** Demo tokens; a real service would verify a JWT or a session here. */
const TOKENS: Record<string, string> = { "ana-token": "ana@acme.com", "bob-token": "bob@acme.com" };

export default definePreHook(
  async (repos, req, _res, args) => {
    const token = req.headers.get("authorization")?.replace(/^Bearer /, "");
    const email = token ? TOKENS[token] : undefined;
    const user = email ? await repos.users.where((u) => u.email.eq(email)).firstOrDefault() : null;
    if (!user) throw new HttpError(401, "Authentication required");
    if (args.length > 0 && !args.includes(user.role)) throw new HttpError(403, `Requires role: ${args.join(" or ")}`);
    req.context.user = user;
  },
  { docs: { responses: [401, 403], security: "bearer" } },
);
```

Este post-hook recebe o corpo da resposta como `data` e retorna o corpo que será enviado no lugar:

```ts check title="hooks/stripTimestamps.ts"
import { definePostHook } from "@quickservice/core";

type Item = Record<string, unknown>;
const strip = ({ createdAt, updatedAt, ...rest }: Item) => rest;

/** Removes createdAt and updatedAt from a record or from each record of a list. */
export default definePostHook((data) => {
  const body = data as Item & { data?: Item[] };
  return Array.isArray(body.data) ? { ...body, data: body.data.map(strip) } : strip(body);
});
```

| | Assinatura | Retorna |
| --- | --- | --- |
| `definePreHook(fn, options?)` | `fn(repos, req, res, args)` | nada; lance um erro para interromper a requisição |
| `definePostHook(fn, options?)` | `fn(data, repos, req, res, args)` | o corpo da resposta (alterado ou não) |

`repos`, `req` e `res` são os mesmos objetos que o handler recebe (veja [Endpoints personalizados e substituições](/pt-br/guides/endpoints/#a-requisição-req)), então hooks podem consultar repositórios, ler headers, compartilhar valores por `req.context` e definir headers ou o status com `res`. `args` traz os argumentos escritos na tag.

Nomes de hook seguem `^[a-z][a-zA-Z0-9]*$` e não podem ser o nome de uma tag embutida. Caso contrário, o build falha:

```text
hooks/Audit.ts: hook file names must match ^[a-z][a-zA-Z0-9]*$
hooks/internal.ts: "internal" is a reserved tag name and cannot be used as a hook
```

## Ligando hooks a uma entidade

Em uma entidade, uma tag de hook vale para as rotas geradas dela. Acrescente `:` e operações para limitá-la a algumas delas (`list`, `read`, `create`, `update`, `replace`, `delete`), e escreva os argumentos depois de um espaço, separados por vírgulas:

```ts check title="entities/User.ts"
export type User = {
  /** @unique @format email */
  email: string;
  name: string;
  /** @default 'member' */
  role: "member" | "admin";
  /** @default true */
  active: boolean;
  age?: number;
  /** @hidden */
  passwordHash?: string;
};
```

```ts check title="entities/Organization.ts"
import type { User } from "./User";

/**
 * @authorized:create,update,replace,delete admin
 * @stripTimestamps:list,read
 */
export type Organization = {
  name: string;
  /** @unique */
  slug: string;
  plan: "free" | "pro";
  members: User[];
  owner?: User;
};
```

Agora, escrever em organizações exige um admin, e as leituras deixam de fora os timestamps:

```bash
curl -X POST localhost:3000/organizations -H "content-type: application/json" \
  -d '{"name":"Acme","slug":"acme","plan":"pro"}'
```

```json
{"error":{"code":"UNAUTHORIZED","message":"Authentication required"}}
```

```bash
curl -X PATCH localhost:3000/organizations/01a146df-3ac8-708f-b7c9-41c6d71b7b77 \
  -H "authorization: Bearer bob-token" -H "content-type: application/json" -d '{"plan":"free"}'
```

```json
{"error":{"code":"FORBIDDEN","message":"Requires role: admin"}}
```

```bash
curl localhost:3000/organizations
```

```json
{"data":[{"id":"01a146df-3ac8-708f-b7c9-41c6d71b7b77","name":"Acme","slug":"acme","plan":"pro","members":["01a146df-3abd-7476-b543-122e8cd8986b"],"owner":"01a146df-3abd-7476-b543-122e8cd8986b"}],"total":1,"limit":20,"offset":0}
```

Sem escopo, um hook vale para as seis operações. Os argumentos são aparados, e uma tag sem argumentos recebe `[]`.

## Ligando hooks a um endpoint

Em um endpoint personalizado, escreva a tag do hook no comentário JSDoc do export padrão, junto de `@summary` e `@description`:

```ts check title="endpoints/users/me/get.ts"
import type { Endpoint } from "@quickservice/core";
import type { User } from "../../../entities/User";

/**
 * @summary The signed-in user
 * @authorized
 */
const handler: Endpoint<unknown, User> = (repos, req) => req.context.user as User;

export default handler;
```

```bash
curl localhost:3000/users/me
```

```json
{"error":{"code":"UNAUTHORIZED","message":"Authentication required"}}
```

```bash
curl localhost:3000/users/me -H "authorization: Bearer bob-token"
```

```json
{"email":"bob@acme.com","name":"Bob","role":"member","active":true,"id":"01a146df-3ac1-7569-b48b-fb50267f5013","createdAt":"2026-10-16T22:39:57.121Z","updatedAt":"2026-10-16T22:39:57.121Z","age":null}
```

Tags de endpoint aceitam argumentos do mesmo jeito (`@authorized admin,owner`), mas não escopo de operação.

## A ordem em que os hooks rodam

Em cada requisição:

1. Os pre-hooks rodam um a um, na ordem das tags.
2. O handler roda. Em endpoints com [query items tipados](/pt-br/guides/query-items/), a query é validada antes, depois dos pre-hooks.
3. Os post-hooks rodam um a um, na ordem das tags, cada um recebendo o corpo retornado pelo anterior.

Quando um pre-hook lança um erro, nada depois dele roda (nem os pre-hooks seguintes, nem o handler, nem os post-hooks) e o erro vira a resposta, como no 401 acima. Os post-hooks são pulados quando o handler retorna `undefined` (um 204) ou um `Response` nativo. Em endpoints com `@fields` ou `@exclude`, os post-hooks recebem o corpo depois de esses campos serem aplicados.

A linha de log de cada requisição lista os hooks que rodaram:

```json
{"timestamp":"2026-10-16T22:39:57.127Z","requestId":"01a146df-3ac5-73f9-b3bc-2917189a1589","method":"GET","route":"/users/me","status":200,"durationMs":1.913,"hooks":["authorized"]}
```

## Hooks em rotas substituídas

Quando um endpoint personalizado [substitui uma rota gerada](/pt-br/guides/endpoints/#substituindo-uma-rota-gerada), a tag `@overrideHooks` da entidade decide quais hooks rodam:

- `inherit` (o padrão): os hooks da entidade para aquela operação, depois os hooks do próprio endpoint. Um hook presente nos dois roda uma vez só, na posição do endpoint e com os argumentos do endpoint.
- `replace`: só os hooks do endpoint.

Por exemplo, com a entidade `Organization` acima e esta substituição da rota de leitura:

```ts check title="endpoints/organizations/[orgId]/get.ts"
import type { Endpoint } from "@quickservice/core";

/** @authorized @audit */
const handler: Endpoint = (repos, req) => repos.organizations.where((o) => o.id.eq(req.params.orgId!)).first();

export default handler;
```

| `Organization` tem | Lista de hooks | Ordem de execução |
| --- | --- | --- |
| nenhum `@overrideHooks` (inherit) | `stripTimestamps`, `authorized`, `audit` | `authorized`, `audit`, handler, `stripTimestamps` |
| `@overrideHooks replace` | `authorized`, `audit` | `authorized`, `audit`, handler |

Pre-hooks sempre rodam antes do handler e post-hooks depois, qualquer que seja a posição deles na lista. Com o padrão `inherit`:

```bash
curl localhost:3000/organizations/01a146e0-35c3-71bf-93c3-f0ecc561c387 -H "authorization: Bearer ana-token"
```

```json
{"id":"01a146e0-35c3-71bf-93c3-f0ecc561c387","name":"Acme","slug":"acme","plan":"pro","members":[],"owner":null}
```

Com `@overrideHooks replace`, a resposta mantém `createdAt` e `updatedAt`, porque `stripTimestamps` não roda mais:

```bash
curl localhost:3000/organizations/01a146e0-3993-7218-93c7-2685a1398537 -H "authorization: Bearer ana-token"
```

```json
{"id":"01a146e0-3993-7218-93c7-2685a1398537","createdAt":"2026-10-16T22:41:02.355Z","updatedAt":"2026-10-16T22:41:02.355Z","name":"Acme","slug":"acme","plan":"pro","members":[],"owner":null}
```

## Verificações do build

O build confere toda tag de hook e falha com uma mensagem que cita o arquivo:

```text
endpoints/health/get.ts: unknown hook @authorize (no hooks/authorize.ts)
endpoints/health/get.ts: hook @authorized is declared more than once
entities/Organization.ts: invalid @authorized: unknown operation "remove" (use list, read, create, update, replace, delete)
```

## Hooks na documentação da API

Toda operação com hooks ganha uma linha `Hooks: ...` na descrição (com argumentos, como em `Hooks: authorized(admin)`) e uma lista `x-hooks`. O `options.docs` de um hook acrescenta mais:

- `responses: [401, 403]` adiciona essas respostas de erro, com o schema compartilhado `Error`, a toda operação que usa o hook.
- `security: "bearer"` define o esquema `bearerAuth` (`type: http`, `scheme: bearer`) uma vez e marca cada uma dessas operações com `security: [{ bearerAuth: [] }]`, para que quem lê a documentação saiba que precisa enviar um token bearer.

Operações sem esses hooks não têm entrada `security`.

```bash
curl -s localhost:3000/openapi.json | jq '.paths["/users/me"].get | {summary, description, "x-hooks", security, responses: (.responses | map_values(.content."application/json".schema))}'
```

```json
{
  "summary": "The signed-in user",
  "description": "Hooks: authorized",
  "x-hooks": [{ "name": "authorized", "phase": "pre", "args": [] }],
  "security": [{ "bearerAuth": [] }],
  "responses": {
    "200": { "$ref": "#/components/schemas/User" },
    "401": { "$ref": "#/components/schemas/Error" },
    "403": { "$ref": "#/components/schemas/Error" }
  }
}
```
