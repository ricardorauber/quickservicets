Endpoints and hooks receive `repos`, with one repository per entity. Besides `create`, `findById`, `update` and the other single-record methods, every repository starts a typed query: you filter with lambdas, chain ordering and paging, and finish with a terminal method such as `toArray()` or `first()`.

```ts check
import type { Repositories } from "@quickservicets/core";

export async function activeAdmins(repos: Repositories) {
  return repos.users
    .where((u) => u.role.eq("admin").and(u.active.eq(true)))
    .orderBy((u) => u.name)
    .toArray();
}
```

Field names, operators and values are checked by TypeScript, and every method returns a new query, so you can keep a base query and extend it.

## The samples on this page

The samples use `User`, `Organization` (with `members: User[]` and `owner?: User`) and `Project` (with `organization: Organization`) entities, and this data:

| User | `role` | `active` | `age` | Organization |
| --- | --- | --- | --- | --- |
| Ana (`ana@acme.com`) | admin | true | 34 | Acme (owner) |
| Bob (`bob@acme.com`) | member | false | 28 | Acme |
| Cid (`cid@globex.com`) | member | true | 41 | Globex |
| Dee (`dee@globex.com`) | admin | true | 25 | Globex |

The users were created in that order. The projects are Website (Acme) and App (Globex). Comments such as `// ["Dee", "Ana"]` show the names of the records each query returns.

## Starting a query

`where(lambda)` starts a filtered query and `query()` starts one over every record:

```ts check
import type { Repositories } from "@quickservicets/core";

export async function starts(repos: Repositories) {
  const admins = await repos.users.where((u) => u.role.eq("admin")).toArray(); // ["Dee", "Ana"]
  const everyone = await repos.users.query().toArray(); // ["Dee", "Cid", "Bob", "Ana"]
  return { admins, everyone };
}
```

Without ordering, results come newest first (`createdAt` descending, then `id` descending). Records come back exactly like the repository's other reads return them: `@hidden` fields removed, derived relation sides and file URLs filled in.

## Conditions per field type

The lambda receives one handle per stored field, plus `id`, `createdAt` and `updatedAt`. Each handle offers the operators that fit its type, the same ones as the `where` filters of the generated list routes:

| Field type | Operators |
| --- | --- |
| Every scalar: string, number, boolean, `Date`, enum, single reference | `eq`, `ne`, `in`, `nin`, `exists`, `isNull` |
| Numbers and dates | also `gt`, `gte`, `lt`, `lte` |
| Strings (not enums or unions) | also `contains`, `startsWith` |
| Reference arrays (`members: User[]`) | `contains`, `containsAny`, `containsAll`, `isEmpty` |

```ts check
import type { Repositories } from "@quickservicets/core";

export async function conditions(repos: Repositories, anaId: string, bobId: string, cidId: string, deeId: string, acmeId: string) {
  // Strings: contains and startsWith ignore case and match the text literally.
  await repos.users.where((u) => u.email.contains("ACME")).toArray(); // ["Bob", "Ana"]
  await repos.users.where((u) => u.name.startsWith("d")).toArray(); // ["Dee"]

  // Numbers and dates compare.
  await repos.users.where((u) => u.age.lt(30)).toArray(); // ["Dee", "Bob"]
  await repos.users.where((u) => u.createdAt.gte(new Date("2026-01-01"))).count(); // 4

  // Lists of values.
  await repos.users.where((u) => u.id.in([anaId, cidId])).toArray(); // ["Cid", "Ana"]
  await repos.users.where((u) => u.role.nin(["admin"])).toArray(); // ["Cid", "Bob"]

  // exists() and isNull() mean true; pass false for the opposite.
  await repos.users.where((u) => u.age.isNull()).toArray(); // []
  await repos.organizations.where((o) => o.owner.exists()).toArray(); // ["Acme"]

  // A single reference holds an id.
  await repos.projects.where((p) => p.organization.eq(acmeId)).toArray(); // ["Website"]

  // Reference arrays.
  await repos.organizations.where((o) => o.members.contains(bobId)).toArray(); // ["Acme"]
  await repos.organizations.where((o) => o.members.containsAny([anaId, deeId])).toArray(); // ["Globex", "Acme"]
  await repos.organizations.where((o) => o.members.containsAll([cidId, deeId])).toArray(); // ["Globex"]
  await repos.organizations.where((o) => o.members.isEmpty()).toArray(); // []
}
```

Mistakes fail to type-check instead of failing at runtime:

```ts
repos.users.where((u) => u.emial.eq("x")); // Property 'emial' does not exist. Did you mean 'email'?
repos.users.where((u) => u.age.gte("30")); // Argument of type 'string' is not assignable to parameter of type 'number'.
repos.users.where((u) => u.role.contains("adm")); // Property 'contains' does not exist: role is an enum.
```

Objects, arrays of plain values and computed file URLs cannot be filtered.

## Combining conditions: `and`, `or`, `not` and chained `where`

Inside a lambda, `.and(...)` and `.or(...)` combine conditions, and `.not()` negates the condition it is called on. They nest the way you call them: `a.and(b.or(c))` is `a AND (b OR c)`, `a.or(b).and(c)` is `(a OR b) AND c`, and `a.and(b.or(c).not())` is `a AND NOT (b OR c)`. Each further `.where(...)` adds conditions with AND.

```ts check
import type { Repositories } from "@quickservicets/core";

export async function combined(repos: Repositories) {
  // AND inside one lambda, or across chained where calls: the same result.
  await repos.users.where((u) => u.role.eq("member").and(u.active.eq(true))).toArray(); // ["Cid"]
  await repos.users.where((u) => u.role.eq("member")).where((u) => u.active.eq(true)).toArray(); // ["Cid"]

  // OR.
  await repos.users.where((u) => u.role.eq("admin").or(u.email.contains("@globex.com"))).toArray(); // ["Dee", "Cid", "Ana"]

  // AND with a nested OR: active, and either 30 or older or an admin.
  await repos.users.where((u) => u.active.eq(true).and(u.age.gte(30).or(u.role.eq("admin")))).toArray(); // ["Dee", "Cid", "Ana"]

  // NOT of a compound condition: everyone except active admins.
  await repos.users.where((u) => u.role.eq("admin").and(u.active.eq(true)).not()).toArray(); // ["Cid", "Bob"]

  // NOT nested inside OR: members, or anyone not 30 or older.
  await repos.users.where((u) => u.role.eq("member").or(u.age.gte(30).not())).toArray(); // ["Dee", "Cid", "Bob"]
}
```

OR and NOT work on every database adapter, including conditions on reference arrays and derived relation sides, `related` queries and the conditions of aggregate counts.

### `.not()` and missing values

Comparisons never match a field that is `null` or missing: a user without an `age` matches neither `u.age.lt(30)` nor `u.age.gte(30)`, and `u.age.ne(30)` leaves them out too, as in SQL. `.not()` works like `!` in JavaScript instead: it matches every record for which the condition is not true, so such a user matches `u.age.gte(30).not()`. Use `.not()` when "not this" should include the records without a value, and `ne`, `nin` or `lt` when it should not:

| Condition | A user aged 25 | A user aged 41 | A user without an `age` |
| --- | --- | --- | --- |
| `u.age.lt(30)` | matches | | |
| `u.age.gte(30)` | | matches | |
| `u.age.gte(30).not()` | matches | | matches |

Every adapter gives the same results: SQL databases run the negation as `(<condition>) IS NOT TRUE` and MongoDB as `$nor`.

## Ordering: `orderBy`, `orderByDescending`, `thenBy`, `thenByDescending`

`orderBy` and `orderByDescending` set the first sort field and replace any earlier ordering; `thenBy` and `thenByDescending` add more. `id` is always the last tie-breaker, so the order is stable.

```ts check
import type { Repositories } from "@quickservicets/core";

export async function ordered(repos: Repositories) {
  await repos.users.query().orderBy((u) => u.name).toArray(); // ["Ana", "Bob", "Cid", "Dee"]
  await repos.users.query().orderByDescending((u) => u.age).toArray(); // ["Cid", "Ana", "Bob", "Dee"]
  await repos.users.query().orderBy((u) => u.role).thenBy((u) => u.name).toArray(); // ["Ana", "Dee", "Bob", "Cid"]
  await repos.users.query().orderBy((u) => u.role).thenByDescending((u) => u.age).toArray(); // ["Ana", "Dee", "Cid", "Bob"]
}
```

You can order by the fields the list routes can sort by: scalars, dates and single references. Reference arrays and derived relation sides fail to type-check:

```ts
repos.organizations.query().orderBy((o) => o.members); // Property 'members' does not exist on type 'SortFields<Organization>'.
```

## Slicing: `skip` and `take`

`skip(n)` leaves out the first `n` results and `take(n)` returns at most `n`. They apply to `toArray()`, `first()`, `firstOrDefault()` and `page()`, but not to `count()`, `any()`, `all()` and `none()`. A negative or fractional value throws a 400 `Invalid query`, with details such as `skip: Must be an integer of at least 0`.

```ts check
import type { Repositories } from "@quickservicets/core";

export async function sliced(repos: Repositories) {
  const byName = repos.users.query().orderBy((u) => u.name);
  await byName.skip(1).take(2).toArray(); // ["Bob", "Cid"]
  await byName.skip(1).take(2).count(); // 4
}
```

## Choosing fields: `select`

`select(...fields)` returns only those fields plus `id`, and the result type is narrowed to match:

```ts check
import type { Repositories } from "@quickservicets/core";

export async function selected(repos: Repositories) {
  const admins = await repos.users.where((u) => u.role.eq("admin")).orderBy((u) => u.name).select("name", "email").toArray();
  // [{ id: "...", name: "Ana", email: "ana@acme.com" }, { id: "...", name: "Dee", email: "dee@globex.com" }]
  return admins.map((user) => `${user.name} <${user.email}>`);
}
```

Unknown fields fail to type-check, and so do fields you left out: after `select("name")`, `user.email` is an error.

## Loading related records: `include`

`include(...paths)` replaces reference ids with the referenced records. Paths can go several levels deep (`organization.members`), and the result is typed at every level:

```ts check
import type { Repositories } from "@quickservicets/core";

export async function included(repos: Repositories) {
  const projects = await repos.projects.query().orderBy((p) => p.name).include("organization").toArray();
  const pairs = projects.map((project) => [project.name, project.organization?.name]); // [["App", "Globex"], ["Website", "Acme"]]

  const website = await repos.projects.where((p) => p.name.eq("Website")).include("organization.members").first();
  const members = website.organization?.members.map((user) => user.name); // ["Ana", "Bob"]
  return { pairs, members };
}
```

A path that does not exist fails to type-check:

```ts
repos.projects.query().include("organization.member");
// Argument of type '"organization.member"' is not assignable to parameter of type
// '"organization" | "organization.owner" | "organization.members"'.
```

`include` follows the same rules as the `populate` read option. A path can have at most `populate.maxDepth` segments (2 by default); longer paths fail with `Populate depth exceeds 2`. Raise the limit in the [configuration](/reference/config/).

An endpoint can return an included record directly. This override of the generated read route answers with the project's organization populated:

```ts check title="endpoints/projects/[id]/get.ts"
import type { Endpoint } from "@quickservicets/core";

/** Reads a project with its organization populated. */
const handler: Endpoint = (repos, req) => repos.projects.where((p) => p.id.eq(req.params.id!)).include("organization").first();

export default handler;
```

## Querying a record's reference array: `related`

`related(id, field)` starts a query over the records that the reference array `field` of record `id` lists. It replaces loading the record and then filtering by its ids, and it runs as one query:

```ts check
import type { Repositories } from "@quickservicets/core";

export async function relatedRecords(repos: Repositories, acmeId: string, globexId: string) {
  const acme = await repos.organizations.related(acmeId, "members").toArray(); // ["Bob", "Ana"]
  const admins = await repos.organizations.related(globexId, "members").where((u) => u.role.eq("admin")).toArray(); // ["Dee"]
  const members = await repos.organizations.related(globexId, "members").count(); // 2
  return { acme, admins, members };
}
```

The query is over the array's target entity (`User` here), so `where`, ordering, `select`, `include` and every terminal method work as on `repos.users`. Results come in the usual default order, not in the array's order; add `orderBy` for another one. When the record does not exist or its array is empty, the query has no records: `toArray()` returns `[]`, `count()` 0, `any()` `false`, and `all(condition)` and `none()` `true`.

`aggregate` tells the two cases apart: it returns `null` when the record does not exist, and over an empty array counts are `0` and the other aggregates `null`. An endpoint can therefore answer 404 without reading the record first:

```ts check title="endpoints/organizations/[id]/stats/get.ts"
import { HttpError, type Endpoint } from "@quickservicets/core";

/** Counts the members and admins of an organization and averages their ages. */
const handler: Endpoint = async (repos, req) => {
  const stats = await repos.organizations
    .related(req.params.id!, "members")
    .aggregate((u) => ({ members: u.count(), admins: u.count(u.role.eq("admin")), averageAge: u.age.avg() }));
  if (!stats) throw new HttpError(404, "Organization not found");
  return stats; // Acme: { members: 2, admins: 1, averageAge: 31 }
};

export default handler;
```

On PostgreSQL and SQLite this is one statement: the organization left-joined to its `members` and to the matching users. On MongoDB, the organization's array is read first and the users are then queried by it.

`field` must be a reference array the entity stores (`members: User[]`). Other fields, single references and the derived sides of relations fail to type-check:

```ts
repos.organizations.related(id, "name"); // Argument of type '"name"' is not assignable to parameter of type '"members"'.
```

## Running the query

A query does nothing until you call one of its terminal methods.

### `toArray`

Every match, as an array. To protect the server, `toArray()` loads at most one record more than `repositories.toArrayMax` (10000 by default, `QS_REPOSITORIES_TO_ARRAY_MAX` overrides it), after `skip` and `take`, and throws when that extra record is there:

```text
Query on User matched more than repositories.toArrayMax (2) records
```

Use `take(n)` or `page()` for large tables, or raise the limit in `quickservicets.config.ts`:

```ts check title="quickservicets.config.ts"
import { defineConfig, memoryAdapter } from "@quickservicets/core";

export default defineConfig({
  database: memoryAdapter(),
  repositories: { toArrayMax: 50_000 },
});
```

### `first` and `firstOrDefault`

`first()` returns the first match or fails with 404 `<Entity> not found`, which becomes the response when thrown in an endpoint (see `GET /projects/missing` above). `firstOrDefault()` returns `null` instead.

```ts check
import type { Repositories } from "@quickservicets/core";

export async function firsts(repos: Repositories) {
  const youngest = await repos.users.query().orderBy((u) => u.age).first(); // Dee
  const zoe = await repos.users.where((u) => u.email.eq("zoe@acme.com")).firstOrDefault(); // null
  return { youngest, zoe };
}
```

### `count`, `any`, `all` and `none`

`toArray()` reads the records; `count()`, `any()`, `all()` and `none()` answer about them without loading any:

- `count()` is the number of matches.
- `any()` is whether at least one record matches; `any(condition)` is whether at least one match also satisfies the condition.
- `all(condition)` is whether every match satisfies the condition. It is `true` when nothing matches, and the database answers it in one round trip by counting the matches and the matches that satisfy the condition together.
- `none()` is whether nothing matches; `none(condition)` is whether no match satisfies the condition. It is always the opposite of `any()` with the same condition, and runs as one count.

Like `count()`, `any()`, `all()` and `none()` look at every match of the query's `where` conditions, ignoring `skip` and `take`.

```ts check
import type { Repositories } from "@quickservicets/core";

export async function counts(repos: Repositories) {
  const admins = repos.users.where((u) => u.role.eq("admin"));
  const active = await repos.users.where((u) => u.active.eq(true)).count(); // 3
  const hasAdmins = await admins.any(); // true
  const hasYoungAdmin = await admins.any((u) => u.age.lt(30)); // true (Dee)
  const adminsActive = await admins.all((u) => u.active.eq(true)); // true
  const membersActive = await repos.users.where((u) => u.role.eq("member")).all((u) => u.active.eq(true)); // false (Bob)
  const adminList = await admins.toArray(); // ["Dee", "Ana"]
  return { active, hasAdmins, hasYoungAdmin, adminsActive, membersActive, adminList };
}
```

The same question can be asked several ways. With `.not()`, "every admin is active" is also "no admin is inactive", and "some admin is inactive" is its opposite:

```ts check
import type { Repositories } from "@quickservicets/core";

export async function sideBySide(repos: Repositories) {
  const admins = repos.users.where((u) => u.role.eq("admin"));
  const someInactive = await admins.any((u) => u.active.eq(true).not()); // false
  const allActive = await admins.all((u) => u.active.eq(true)); // true
  const noneInactive = await admins.none((u) => u.active.eq(true).not()); // true, the same as allActive
  const noAdmins = await admins.none(); // false
  const noneOver40 = await repos.users.query().none((u) => u.age.gt(40)); // false (Cid)
  return { someInactive, allActive, noneInactive, noAdmins, noneOver40 };
}
```

`all()` needs a condition: without one it fails to type-check, and at runtime it throws `all() needs a condition; use toArray() to read the records`.

### Asking the repository directly

For a yes/no or count question about the whole entity, call `any`, `all`, `none` and `count` on the repository itself: each is the same terminal on `query()`, and `count(condition)` is `where(condition).count()`.

```ts check
import type { Repositories } from "@quickservicets/core";

export async function shortcuts(repos: Repositories) {
  const hasAdmins = await repos.users.any((u) => u.role.eq("admin")); // true, like repos.users.query().any(...)
  const allHaveEmail = await repos.users.all((u) => u.email.contains("@")); // true
  const noneOver60 = await repos.users.none((u) => u.age.gt(60)); // true
  const activeUsers = await repos.users.count((u) => u.active.eq(true)); // 3
  const users = await repos.users.count(); // 4
  return { hasAdmins, allHaveEmail, noneOver60, activeUsers, users };
}
```

### `aggregate`

`aggregate(lambda)` computes counts, sums, averages, minimums and maximums of the matches in one database round trip (one SQL statement, or one MongoDB pipeline), without loading records. The lambda receives the same field handles as `where`, plus `count()`, and returns an object of aggregate expressions; the result has the same keys:

```ts check
import type { Repositories } from "@quickservicets/core";

export async function stats(repos: Repositories) {
  const users = await repos.users.query().aggregate((u) => ({
    users: u.count(), // 4
    admins: u.count(u.role.eq("admin")), // 2
    activeOrYoung: u.count(u.active.eq(true).or(u.age.lt(30))), // 4
    notActiveAdmins: u.count(u.role.eq("admin").and(u.active.eq(true)).not()), // 2
    totalAge: u.age.sum(), // 128
    averageAge: u.age.avg(), // 32
    youngest: u.age.min(), // 25
    oldest: u.age.max(), // 41
    newest: u.createdAt.max(), // Dee's createdAt, a Date
  }));
  const acme = await repos.users.where((u) => u.email.contains("@acme.com")).aggregate((u) => ({ members: u.count(), averageAge: u.age.avg() }));
  // { members: 2, averageAge: 31 }
  return { users, acme };
}
```

| Expression | On | Result |
| --- | --- | --- |
| `f.count()` | the query | The number of matches |
| `f.count(condition)` | the query | The number of matches that also satisfy `condition`, written like a `where` condition (`and`, `or`, `not`) |
| `f.<field>.sum()`, `.avg()` | number fields | A number, or `null` |
| `f.<field>.min()`, `.max()` | number and date fields | A number or a `Date`, or `null` |

Like SQL, `sum`, `avg`, `min` and `max` skip `null` values and are `null` when no match has a value; counts are `0`. The query's conditions apply, including OR and NOT groups and conditions on derived relation sides; `skip`, `take`, ordering, `select` and `include` do not.

```ts check
import type { Repositories } from "@quickservicets/core";

export async function noMatches(repos: Repositories) {
  return repos.users.where((u) => u.email.contains("@initech.com")).aggregate((u) => ({ members: u.count(), averageAge: u.age.avg() }));
  // { members: 0, averageAge: null }
}
```

The result type follows from the expressions (`{ members: number; averageAge: number | null }` above), and expressions that do not fit the field fail to type-check:

```ts
repos.users.query().aggregate((u) => ({ total: u.email.sum() })); // Property 'sum' does not exist: email is a string.
repos.users.query().aggregate((u) => ({ total: u.createdAt.sum() })); // Property 'sum' does not exist: dates only have min and max.
```

### `page`

`page({ limit, offset })` returns `{ data, total, limit, offset }`, the same shape as the generated list routes. `limit` goes from 1 to 100 (default 20) and `offset` from 0 (default 0); other values throw a 400 `Invalid query` before the database is queried, with the same details as the list routes' parameters: `limit: Must be an integer from 1 to 100` and `offset: Must be an integer of at least 0`.

```ts check
import type { Repositories } from "@quickservicets/core";

export async function paged(repos: Repositories) {
  return repos.users.query().orderBy((u) => u.name).page({ limit: 2, offset: 2 });
  // { data: [Cid, Dee], total: 4, limit: 2, offset: 2 }
}
```

## Loading many records by id: `findByIds`

`findByIds(ids, { include })` returns the records for `ids` in the same order, skipping ids without a record and never repeating one. It loads them in batches, so long lists are fine. `include` populates like the `include` of a query.

```ts check
import type { Repositories } from "@quickservicets/core";

export async function byIds(repos: Repositories, anaId: string, cidId: string, globexId: string) {
  const users = await repos.users.findByIds([cidId, anaId, "missing", anaId]); // ["Cid", "Ana"]
  const [globex] = await repos.organizations.findByIds([globexId], { include: ["members"] });
  const members = globex?.members.map((user) => user.name); // ["Cid", "Dee"]
  return { users, members };
}
```
