A hook is a small piece of code that runs around a handler: a **pre-hook** runs before it (to authenticate, check permissions, load something into `req.context`), and a **post-hook** runs after it and can change the response body. You write each hook once in `hooks/` and attach it with a JSDoc tag, on an entity for its generated routes or on any custom endpoint.

## Writing a hook

Each file in `hooks/` default-exports the result of `definePreHook` or `definePostHook`, and the file name is the hook's name. This pre-hook checks a bearer token, optionally checks the user's role, and keeps the user in `req.context` for the handler:

```ts check title="hooks/authorized.ts"
import { definePreHook, HttpError } from "@quickservicets/core";

/** Demo tokens; a real service would verify a JWT or a session here. */
const TOKENS: Record<string, string> = { "ana-token": "ana@acme.com", "bob-token": "bob@acme.com" };

export default definePreHook(
  async (repos, req, _res, args) => {
    const token = req.headers.get("authorization")?.replace(/^Bearer /, "");
    const email = token ? TOKENS[token] : undefined;
    const user = email ? await repos.users.where((u) => u.email.eq(email)).firstOrDefault() : null;
    if (!user) throw new HttpError(401, "Authentication required");
    if (args.length > 0 && !args.includes(user.role)) throw new HttpError(403, `Requires role: ${args.join(" or ")}`);
    req.context.user = user;
  },
  { docs: { responses: [401, 403], security: "bearer" } },
);
```

This post-hook receives the response body as `data` and returns the body to send instead:

```ts check title="hooks/stripTimestamps.ts"
import { definePostHook } from "@quickservicets/core";

type Item = Record<string, unknown>;
const strip = ({ createdAt, updatedAt, ...rest }: Item) => rest;

/** Removes createdAt and updatedAt from a record or from each record of a list. */
export default definePostHook((data) => {
  const body = data as Item & { data?: Item[] };
  return Array.isArray(body.data) ? { ...body, data: body.data.map(strip) } : strip(body);
});
```

| | Signature | Returns |
| --- | --- | --- |
| `definePreHook(fn, options?)` | `fn(repos, req, res, args)` | nothing; throw to stop the request |
| `definePostHook(fn, options?)` | `fn(data, repos, req, res, args)` | the (possibly changed) response body |

`repos`, `req` and `res` are the same objects the handler gets (see [Custom endpoints and overrides](/guides/endpoints/#the-request-req)), so hooks can query repositories, read headers, share values through `req.context` and set headers or the status with `res`. `args` holds the arguments written in the tag.

Hook names match `^[a-z][a-zA-Z0-9]*$` and cannot be a built-in tag name. The build fails otherwise:

```text
hooks/Audit.ts: hook file names must match ^[a-z][a-zA-Z0-9]*$
hooks/internal.ts: "internal" is a reserved tag name and cannot be used as a hook
```

## Attaching hooks to an entity

On an entity, a hook tag applies to its generated routes. Add `:` and operations to limit it to some of them (`list`, `read`, `create`, `update`, `replace`, `delete`), and write arguments after a space, separated by commas:

```ts check title="entities/User.ts"
export type User = {
  /** @unique @format email */
  email: string;
  name: string;
  /** @default 'member' */
  role: "member" | "admin";
  /** @default true */
  active: boolean;
  age?: number;
  /** @hidden */
  passwordHash?: string;
};
```

```ts check title="entities/Organization.ts"
import type { User } from "./User";

/**
 * @authorized:create,update,replace,delete admin
 * @stripTimestamps:list,read
 */
export type Organization = {
  name: string;
  /** @unique */
  slug: string;
  plan: "free" | "pro";
  members: User[];
  owner?: User;
};
```

Writing to organizations now requires an admin, and reads leave out the timestamps:

```bash
curl -X POST localhost:3000/organizations -H "content-type: application/json" \
  -d '{"name":"Acme","slug":"acme","plan":"pro"}'
```

```json
{"error":{"code":"UNAUTHORIZED","message":"Authentication required"}}
```

```bash
curl -X PATCH localhost:3000/organizations/01a146df-3ac8-708f-b7c9-41c6d71b7b77 \
  -H "authorization: Bearer bob-token" -H "content-type: application/json" -d '{"plan":"free"}'
```

```json
{"error":{"code":"FORBIDDEN","message":"Requires role: admin"}}
```

```bash
curl localhost:3000/organizations
```

```json
{"data":[{"id":"01a146df-3ac8-708f-b7c9-41c6d71b7b77","name":"Acme","slug":"acme","plan":"pro","members":["01a146df-3abd-7476-b543-122e8cd8986b"],"owner":"01a146df-3abd-7476-b543-122e8cd8986b"}],"total":1,"limit":20,"offset":0}
```

Without a scope, a hook applies to all six operations. Arguments are trimmed, and a tag without arguments gets `[]`.

## Attaching hooks to an endpoint

On a custom endpoint, write the hook tag in the JSDoc comment of the default export, next to `@summary` and `@description`:

```ts check title="endpoints/users/me/get.ts"
import type { Endpoint } from "@quickservicets/core";
import type { User } from "../../../entities/User";

/**
 * @summary The signed-in user
 * @authorized
 */
const handler: Endpoint<unknown, User> = (repos, req) => req.context.user as User;

export default handler;
```

```bash
curl localhost:3000/users/me
```

```json
{"error":{"code":"UNAUTHORIZED","message":"Authentication required"}}
```

```bash
curl localhost:3000/users/me -H "authorization: Bearer bob-token"
```

```json
{"email":"bob@acme.com","name":"Bob","role":"member","active":true,"id":"01a146df-3ac1-7569-b48b-fb50267f5013","createdAt":"2026-10-16T22:39:57.121Z","updatedAt":"2026-10-16T22:39:57.121Z","age":null}
```

Endpoint tags take arguments the same way (`@authorized admin,owner`) but no operation scope.

## The order hooks run in

For each request:

1. The pre-hooks run one by one, in the order of their tags.
2. The handler runs. On endpoints with [typed query items](/guides/query-items/), the query is validated first, after the pre-hooks.
3. The post-hooks run one by one, in the order of their tags, each receiving the body returned by the previous one.

When a pre-hook throws, nothing after it runs (no later pre-hook, no handler, no post-hook) and the error becomes the response, as in the 401 above. Post-hooks are skipped when the handler returns `undefined` (a 204) or a native `Response`. On endpoints with `@fields` or `@exclude`, post-hooks receive the body after those fields are applied.

Each request's log line lists the hooks that ran:

```json
{"timestamp":"2026-10-16T22:39:57.127Z","requestId":"01a146df-3ac5-73f9-b3bc-2917189a1589","method":"GET","route":"/users/me","status":200,"durationMs":1.913,"hooks":["authorized"]}
```

## Hooks on overridden routes

When a custom endpoint [replaces a generated route](/guides/endpoints/#overriding-a-generated-route), the entity's `@overrideHooks` tag decides which hooks run:

- `inherit` (the default): the entity's hooks for that operation, then the endpoint's own hooks. A hook in both runs once, at the endpoint's position and with the endpoint's arguments.
- `replace`: only the endpoint's hooks.

For example, with the `Organization` entity above and this override of the read route:

```ts check title="endpoints/organizations/[orgId]/get.ts"
import type { Endpoint } from "@quickservicets/core";

/** @authorized @audit */
const handler: Endpoint = (repos, req) => repos.organizations.where((o) => o.id.eq(req.params.orgId!)).first();

export default handler;
```

| `Organization` has | Hook list | Execution order |
| --- | --- | --- |
| no `@overrideHooks` (inherit) | `stripTimestamps`, `authorized`, `audit` | `authorized`, `audit`, handler, `stripTimestamps` |
| `@overrideHooks replace` | `authorized`, `audit` | `authorized`, `audit`, handler |

Pre-hooks always run before the handler and post-hooks after it, whatever their position in the list. With the default `inherit`:

```bash
curl localhost:3000/organizations/01a146e0-35c3-71bf-93c3-f0ecc561c387 -H "authorization: Bearer ana-token"
```

```json
{"id":"01a146e0-35c3-71bf-93c3-f0ecc561c387","name":"Acme","slug":"acme","plan":"pro","members":[],"owner":null}
```

With `@overrideHooks replace`, the response keeps `createdAt` and `updatedAt`, because `stripTimestamps` no longer runs:

```bash
curl localhost:3000/organizations/01a146e0-3993-7218-93c7-2685a1398537 -H "authorization: Bearer ana-token"
```

```json
{"id":"01a146e0-3993-7218-93c7-2685a1398537","createdAt":"2026-10-16T22:41:02.355Z","updatedAt":"2026-10-16T22:41:02.355Z","name":"Acme","slug":"acme","plan":"pro","members":[],"owner":null}
```

## Build checks

The build checks every hook tag and fails with a message naming the file:

```text
endpoints/health/get.ts: unknown tag @authorize: no hook or feature defines it
endpoints/health/get.ts: hook @authorized is declared more than once
entities/Organization.ts: invalid @authorized: unknown operation "remove" (use list, read, create, update, replace, delete)
```

## Hooks in the API docs

Every operation with hooks gets a `Hooks: ...` line in its description (with arguments, as in `Hooks: authorized(admin)`) and an `x-hooks` list. A hook's `options.docs` adds more:

- `responses: [401, 403]` adds those error responses, with the shared `Error` schema, to every operation that uses the hook.
- `security: "bearer"` defines the `bearerAuth` scheme (`type: http`, `scheme: bearer`) once and marks each of those operations with `security: [{ bearerAuth: [] }]`, so readers of the docs know to send a bearer token.

Operations without such hooks have no `security` entry.

```bash
curl -s localhost:3000/openapi.json | jq '.paths["/users/me"].get | {summary, description, "x-hooks", security, responses: (.responses | map_values(.content."application/json".schema))}'
```

```json
{
  "summary": "The signed-in user",
  "description": "Hooks: authorized",
  "x-hooks": [{ "name": "authorized", "phase": "pre", "args": [] }],
  "security": [{ "bearerAuth": [] }],
  "responses": {
    "200": { "$ref": "#/components/schemas/User" },
    "401": { "$ref": "#/components/schemas/Error" },
    "403": { "$ref": "#/components/schemas/Error" }
  }
}
```
