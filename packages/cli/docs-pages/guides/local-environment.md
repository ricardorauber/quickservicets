# Local environment

> Start the database and every service the project's features need with one command, through a generated Docker Compose file, and run the development server connected to them.

`quickservicets dev --services` starts every service the project needs, its database and whatever its features ask for, in Docker containers, and runs the development server already connected to them:

```bash
bun run quickservicets dev --services
```

It needs Docker with the compose plugin (`docker compose version`). Without it the command exits 1 with `quickservicets dev --services needs Docker with the compose plugin; install it or start the services yourself`. `quickservicets dev` without the flag works exactly as before and starts nothing.

## What is started

The services come from the project's infrastructure description, `describeInfrastructure(config)`:

- the database: a PostgreSQL or MongoDB container for `database` (named `database`) and one per named database (`database-<name>`); SQLite and memory need none;
- MinIO for an S3 storage without an `endpoint`;
- every service an enabled feature declares in its `infra` field, like Redis for a Redis queue broker.

Each service uses the pinned image, ports, health check and local credentials of the core's catalog (`postgres`, `mongodb`, `redis`, `rabbitmq`, `kafka`, `localstack`, `minio`, `azurite`, `vault`, `keycloak`, `meilisearch`, `typesense`, `opensearch`, `consul`, `etcd`, `clamav`, `mailpit`, `otel-collector`, `jaeger` and `ollama`).

The command writes `.generated/dev/compose.yml`, which starts with `# Generated by quickservicets from quickservicets.config.ts. Do not edit.` and is rewritten only when its content changes, then runs `docker compose -f .generated/dev/compose.yml -p <project> up -d --wait` and waits up to `dev.wait` (60 seconds) for every health check. Each service keeps its data in a named volume `<project>_<name>_data`, so a restart keeps the records; the project name is the package name without its scope. It prints one line per service:

```text
Service database (postgres:17.11-alpine) on localhost:5432
Service redis (redis:7.4.1-alpine) on localhost:6379
```

## Connection variables

The development server receives each service's connection variable, like `DATABASE_URL=postgres://postgres:postgres@localhost:5432/app` or `REDIS_URL=redis://localhost:6379`, resolved for `localhost` and the mapped port. A variable already set in the environment or in the project's `.env` files wins, so a real database in `.env` is never replaced. The database connections (`DATABASE_URL`, and `QS_DATABASES_<NAME>_URL` for each named database) are also written to `.env` when it does not set them, so `migration add`, `migrate` and the other commands reach the same databases.

The credentials are local ones from the catalog and are used only by these commands: `--services` and the `services` commands refuse to run with `production: true` or `NODE_ENV=production`, exiting 1 with `Local services are for development only`.

## Options

The `dev` native is enabled by default and adds nothing to a running service; its options only change these commands:

```ts
export default defineConfig({
  database: postgresAdapter({ url: process.env.DATABASE_URL ?? "postgres://postgres:postgres@localhost:5432/app" }),
  dev: {
    services: { database: { port: 5440 }, redis: { image: "redis:7.2.6-alpine" } },
    wait: "2m",
  },
});
```

- `services.<name>`: `enabled` (false leaves the service to you), `image`, `port` (the host port, when the catalog's is taken) and `env` (variables of the container);
- `composeFile`: where the compose file is written (`.generated/dev/compose.yml`);
- `project`: the compose project name;
- `wait`: how long to wait for the health checks.

When a host port is taken, the command exits 1 with `Port <port> for <name> is in use; set dev.services.<name>.port`. A second database of the same kind takes the next port up (5433 for the second PostgreSQL).

## The override file

`dev/compose.override.yml` in the project is passed as a second `-f` file, so the project changes or adds services without editing generated output:

```yaml
services:
  adminer:
    image: adminer:4.8.1
    ports: ["8080:8080"]
```

## The services commands

| Command | What it does |
| --- | --- |
| `quickservicets services up` | Writes the compose file and starts the services, without the development server. |
| `quickservicets services down [--volumes]` | Stops and removes the containers; `--volumes` also removes their data. |
| `quickservicets services status` | One line per service with its state, health and port. |
| `quickservicets services logs [name]` | The logs of every service, or of one. |
| `quickservicets services env [--show]` | The connection variables, with passwords as `[secret]` unless `--show`. |
