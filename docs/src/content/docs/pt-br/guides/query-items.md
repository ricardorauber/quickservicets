Os valores da query string sempre chegam como strings. Em vez de ler `req.query` e converter cada valor na mão, um endpoint GET ou DELETE pode declarar seus query items como um tipo. O framework então converte e valida a query string antes de o handler rodar, entrega um `req.queryItems` tipado e lista os itens na documentação da API.

Os exemplos desta página usam uma entidade `User` com os campos `email`, `name`, `role` (`"member" | "admin"`) e `active`.

<details>
<summary>A parte de <code>.generated/types.ts</code> que estes exemplos usam</summary>

```ts check title=".generated/types.ts"
// Generated by quickservice build (shortened).
import type { Repository } from "@quickservice/core";

export type User = {
  id: string;
  createdAt: Date;
  updatedAt: Date;
  email: string;
  name: string;
  role: "member" | "admin";
  active: boolean;
};
export type UserCreate = { email: string; name: string; role?: "member" | "admin"; active?: boolean };
export type UserUpdate = Partial<UserCreate>;
export type UserReferences = Record<never, never>;

export interface GeneratedRepositories {
  users: Repository<User, UserReferences, UserCreate, UserUpdate>;
}

declare module "@quickservice/core" {
  interface Repositories extends GeneratedRepositories {}
}
```

</details>

## Declarando o tipo da query

Em endpoints GET e DELETE, o primeiro argumento de tipo de `Endpoint<Query, Result>` é o tipo da query. Cada propriedade é um query item:

```ts check title="endpoints/users/search/get.ts"
import type { Endpoint } from "@quickservice/core";

type Search = {
  /** @minLength 2 @maxLength 50 */
  q?: string;
  role?: "member" | "admin";
  active?: boolean;
  since?: Date;
  ids?: string[];
  /** @default 20 @min 1 @max 100 */
  limit?: number;
};

type UserSummary = { id: string; name: string; email: string };

/**
 * @summary Search users
 * @description Matches `q` against names and emails.
 */
const handler: Endpoint<Search, { data: UserSummary[]; total: number }> = async (repos, req) => {
  const { q, role, active, since, ids, limit } = req.queryItems;
  let query = repos.users.query();
  if (q !== undefined) query = query.where((u) => u.name.contains(q).or(u.email.contains(q)));
  if (role !== undefined) query = query.where((u) => u.role.eq(role));
  if (active !== undefined) query = query.where((u) => u.active.eq(active));
  if (since !== undefined) query = query.where((u) => u.createdAt.gte(since));
  if (ids !== undefined) query = query.where((u) => u.id.in(ids));
  const page = await query.orderBy((u) => u.name).select("name", "email").page({ limit });
  return { data: page.data, total: page.total };
};

export default handler;
```

`req.queryItems` é tipado como `Search`: `limit` é um `number`, `since` um `Date`, `active` um `boolean`.

```bash
curl "localhost:3000/users/search?q=ACME&limit=10"
```

```json
{"data":[{"id":"01a146da-b663-7212-b0d6-71457d2a433b","name":"Ana","email":"ana@acme.com"},{"id":"01a146da-b664-72d7-aa2f-7cbd66be8970","name":"Bob","email":"bob@acme.com"}],"total":2}
```

```bash
curl "localhost:3000/users/search?role=member&active=true"
```

```json
{"data":[{"id":"01a146da-b664-72d8-b074-72ee9018fcb1","name":"Cid","email":"cid@globex.com"}],"total":1}
```

O tipo da query pode ser um tipo literal, um alias de tipo ou uma interface. Quando ele está ausente ou é `unknown` (`Endpoint<unknown, Result>`), o endpoint não tem query items e `req.queryItems` é `{}`.

:::note
Em endpoints POST, PUT e PATCH, o primeiro argumento de tipo continua sendo o corpo JSON, e `req.queryItems` é `{}`. Leia a query string deles com `req.query`.
:::

## Tipos suportados

| Tipo do item | Query string | Valor em `req.queryItems` | Erro quando inválido |
| --- | --- | --- | --- |
| `string` | `?q=ana` | `"ana"` | — |
| `number` | `?limit=10` | `10` | `Must be a number` |
| `boolean` | `?active=true` | `true` (só `true` ou `false`) | `Must be true or false` |
| `Date` | `?since=2026-01-01` | um `Date` (ISO 8601) | `Must be an ISO 8601 date` |
| União de strings, enum de strings ou alias (`"member" \| "admin"`, `Role`) | `?role=admin` | `"admin"` | `Must be one of: member, admin` |
| Um array de qualquer um desses (`string[]`, `Array<Role>`) | `?ids=a&ids=b` | `["a", "b"]` | o erro do item, em `ids[1]` |

Os valores são convertidos do mesmo jeito que os filtros `where` das rotas de listagem geradas. Qualquer outro tipo de propriedade faz o build falhar:

```text
endpoints/users/search/get.ts: query item "range" has unsupported type "{ from: number }"
```

Um tipo de query que não é um tipo objeto falha com `the query type must be an object type`.

## Arrays e chaves repetidas

Um item array é lido de chaves repetidas, e cada valor é convertido separadamente:

```bash
curl "localhost:3000/users/search?ids=01a146da-b664-72d8-b074-72ee9018fcb1&ids=01a146da-b663-7212-b0d6-71457d2a433b"
```

```json
{"data":[{"id":"01a146da-b663-7212-b0d6-71457d2a433b","name":"Ana","email":"ana@acme.com"},{"id":"01a146da-b664-72d8-b074-72ee9018fcb1","name":"Cid","email":"cid@globex.com"}],"total":2}
```

Repetir a chave de um item de valor único é um erro:

```bash
curl "localhost:3000/users/search?q=an&q=bo"
```

```json
{"error":{"code":"VALIDATION_ERROR","message":"Invalid query","details":[{"field":"q","message":"Parameter is repeated"}]}}
```

## Itens obrigatórios e opcionais

Um item opcional (`q?: string`) que não foi enviado fica fora de `req.queryItems`. Um item obrigatório ausente falha com `Is required`:

```ts check title="endpoints/users/by-email/get.ts"
import type { Endpoint } from "@quickservice/core";

/** @summary Find a user by email */
const handler: Endpoint<{ email: string }> = (repos, req) =>
  repos.users.where((u) => u.email.eq(req.queryItems.email)).select("name", "email", "role").first();

export default handler;
```

```bash
curl localhost:3000/users/by-email
```

```json
{"error":{"code":"VALIDATION_ERROR","message":"Invalid query","details":[{"field":"email","message":"Is required"}]}}
```

```bash
curl "localhost:3000/users/by-email?email=bob@acme.com"
```

```json
{"id":"01a146da-b664-72d7-aa2f-7cbd66be8970","name":"Bob","email":"bob@acme.com","role":"member"}
```

## Chaves desconhecidas

Chaves que não são itens declarados são ignoradas: não fazem a requisição falhar e não entram em `req.queryItems`. Elas continuam legíveis por `req.query`, que é sempre o `URLSearchParams` cru, então `req.query.get("utm_source")` ainda funciona aqui:

```bash
curl "localhost:3000/users/search?ids=a&ids=b&utm_source=newsletter"
```

```json
{"data":[],"total":0}
```

## Erros de validação

Quando algum item é inválido, o endpoint responde 400 `VALIDATION_ERROR` com a mensagem `Invalid query` e uma entrada em `details` para cada problema, na ordem em que os itens foram declarados. A verificação roda depois dos pre-hooks e antes do handler, então um hook `@authorized` ainda rejeita primeiro quem chama sem autenticação.

```bash
curl "localhost:3000/users/search?limit=abc&active=yes&role=owner&since=yesterday"
```

```json
{"error":{"code":"VALIDATION_ERROR","message":"Invalid query","details":[{"field":"role","message":"Must be one of: member, admin"},{"field":"active","message":"Must be true or false"},{"field":"since","message":"Must be an ISO 8601 date"},{"field":"limit","message":"Must be a number"}]}}
```

## Padrões e limites

Cinco tags JSDoc funcionam em query items:

| Tag | Vale para | Efeito |
| --- | --- | --- |
| `@default <valor>` | qualquer item | Usado quando o item está ausente, então ele sempre está em `req.queryItems`. Strings entre aspas simples (`'name'`), números e booleanos como escritos, datas como strings ISO (`'2026-01-01'`), arrays como JSON (`["a","b"]`). |
| `@min <n>` / `@max <n>` | números | `Must be at least <n>` / `Must be at most <n>` |
| `@minLength <n>` / `@maxLength <n>` | strings | `Must be at least <n> characters` / `Must be at most <n> characters` |

No endpoint de busca, `limit` vale 20 quando o cliente não envia nenhum, e os limites se aplicam depois da conversão:

```bash
curl "localhost:3000/users/search?limit=500&q=a"
```

```json
{"error":{"code":"VALIDATION_ERROR","message":"Invalid query","details":[{"field":"q","message":"Must be at least 2 characters"},{"field":"limit","message":"Must be at most 100"}]}}
```

:::tip
Um item com padrão está sempre presente em tempo de execução, mas sua propriedade continua opcional no tipo (`limit?: number`). Repasse-o como está, como em `page({ limit })` acima, ou escreva `limit ?? 20` se precisar de um `number` simples.
:::

Uma tag que não combina com o item faz o build falhar, assim como qualquer outra tag:

```text
endpoints/users/search/get.ts: query item "q" has invalid @min: only applies to number items
endpoints/users/search/get.ts: query item "limit" has invalid @default: "20" does not match the item type
```

## Query items na documentação da API

Cada item aparece como um parâmetro `in: query` da operação. Ele é `required` quando não é opcional e não tem `@default`, e seu schema traz `default`, `minimum`, `maximum`, `minLength` e `maxLength` das tags. Arrays usam `style: form` e `explode: true`, e enums e aliases nomeados referenciam seu schema compartilhado.

```bash
curl -s localhost:3000/openapi.json | jq '.paths["/users/search"].get.parameters'
```

```json
[
  { "name": "q", "in": "query", "required": false, "schema": { "type": "string", "minLength": 2, "maxLength": 50 } },
  { "name": "role", "in": "query", "required": false, "schema": { "type": "string", "enum": ["member", "admin"] } },
  { "name": "active", "in": "query", "required": false, "schema": { "type": "boolean" } },
  { "name": "since", "in": "query", "required": false, "schema": { "type": "string", "format": "date-time" } },
  { "name": "ids", "in": "query", "required": false, "style": "form", "explode": true, "schema": { "type": "array", "items": { "type": "string" } } },
  { "name": "limit", "in": "query", "required": false, "schema": { "type": "number", "minimum": 1, "maximum": 100, "default": 20 } }
]
```

Quando uma substituição de uma rota de listagem ou leitura gerada (por exemplo `endpoints/users/get.ts`) declara um tipo de query, a documentação lista os itens dela no lugar dos parâmetros gerados `limit`, `offset`, `sort`, `where`, `fields`, `exclude` e `populate`. Sem um tipo de query, a substituição mantém os parâmetros gerados.
